# data 目录说明

这里保存 XUYI 构建、审计和测试需要的源数据与审核 fixture。

## 真源优先级

1. 已由后台管理的产品、页面、Blog、评价、翻译、语言配置和发布状态：Cloudflare D1/CMS。
2. R2 中的原始图片和媒体对象，以及 D1 中的引用、ALT、语言和审核关系。
3. 版本化源目录、模板配置和测试 fixture：只作为构建输入、初始化来源或回归依据，不能覆盖 D1 已审核值。

## 文件分类

- 活动构建输入：被根目录渲染器、Functions、工作流或当前回归测试明确引用的 JSON/媒体。
- 审核基线：用于判断历史源是否被管理员修改；管理员修改后必须优先保留。
- 日期批次：用于已完成发布的审计或可重复回放，不是日常自动发布队列。
- 临时请求/重试/刷新 payload：任务完成且无引用后应删除，不作为业务数据备份。

不要从文件名推断当前产品、语言或文章总数。任何数据清理都必须先核对代码引用和 D1/R2 记录。


## 当前边界

Blog 采购决策表已经回填到 D1 的 `xuyi_blog_posts.content_json.buyerDecisionTable`；产品 SEO 最终字段由 `xuyi_product_seo` 管理。带日期的决策表批次和历史 SEO 刷新清单不再是正式构建输入，也不作为后台发布备份。后续统一通过 D1/CMS 和 R2 维护。
