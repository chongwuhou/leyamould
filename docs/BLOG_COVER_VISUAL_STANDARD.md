# XUYI B2B 博客配图永久硬标准（2026-10-29 起）

> **站长已多次指出：文章与图片不契合。这是 P0 编辑质量问题，不能再以“有图、尺寸合格、CI 通过”充当内容审核通过。** 本标准以 2026-10-29 站长亲选的三张应用场景图为参考。适用于以后每篇新写、重新选图、批量生产和发布的 B2B 博客，所有语言的封面、博客列表卡片及 OG 图均应遵守。以前的图片可以分批审计，不能因为本文件存在就宣称全部合格。

## 1. 选图唯一顺序：**文章题目 → 采购场景 → 客户身份 → 图片内容**

1. **先读完整文章**：标题、用户是谁、采购/使用目的、实际环境、核心商品与规格限制。写出一句能够直接回答“为什么这张图正是这篇文章”的文字；通用、空泛理由不合格。
2. **先选对应行业环境**，而不是先挑一张漂亮的杯子照片：仓储员工与班组→有辨识度的仓储/工业工作环境；机场/车站零售→真实货架/零售陈列和多款水瓶；共享办公礼包→现代共享办公、桌面、会员欢迎场景；学校/营地/活动/酒店/健身房亦须各用对应场景。
3. **水杯用途必须清楚**：照片中最好有可辨认的塑料水杯、展示/采购/使用动作或组合。若选的是行业人物/环境图但没有明确可见水杯，只能作为“场景示意”，须在审核记录中明确注明，并取得站长对这篇文章的例外选择；不能写成该图展示真实订单/型号/工厂实拍。
4. **三秒核对**：不看文件名，只看图片和文章标题，第一次浏览的人应立即感到“这是同一种客户/同一种采购情景”。看不出关联则拒绝。
5. **一篇一图，一批多图不重复凑数**：同一批不同主题不得复用同一张图或只换裁剪/色调。仅因标题出现“water bottle”而使用通用产品特写、儿童款凑成人场景、大水壶凑旅行零售、摄影棚孤立瓶子凑团队欢迎礼包，一律不合格。

## 2. 一票否决

- 画面**主要行业、受众或场景错位**，即使图片漂亮、无版权问题也退回。
- 图中明显是错误产品类别、无关机械/家具、错误场所；不允许声称它是对应型号、客户现场、真实订单、认证或生产实力。
- 随意拿历史 SKU 图片、同一张素材重复用到不相关行业、用假工厂/假客户/虚构品牌/假标签、用带水印/版权不清的网络盗图、过度 AI 假细节或严重扭曲产品。
- 文章封面、博客列表、OG 图、五语页面彼此错用不同图；或后台已经换图却被旧源回退覆盖。
- **没有看过实际图像**，只根据文件名、AI 提示词、自动分数或者源码 JSON 就宣布“图片与文章契合”。

## 3. 图片技术标准（参照今天三张图）

- 主封面 **1200 × 800 px，3:2 横版，WebP，sRGB、清晰自然、主体不裁掉**；目标文件 50–200 KB，允许 30–350 KB（明显异常需重新优化）。
- 优先真实可授权素材或经确认的场景示意图。生成/合成图必须诚实标记为**示意图**，不能当实拍或产品技术证据。不要把“AI 看着像真实”当成客户/厂家证明。
- 同一文章 5 种语言沿用相同封面，alt 文案各语言描述真实所见，不臆造精确 SKU、认证、材质或性能。
- 使用有版本、可追踪 SHA-256 的源文件；Cloudflare R2 使用**唯一新 key**（/media/blog/...），保留旧图可回退。新图先核实 R2 HTTP 200 与 WebP MIME，再更新正式 D1/CMS。不能只改 `dist/`、缓存或构建后 HTML。
- 所有 D1/CMS 站长自己改的图**永远优先**。自动任务只对仍是旧基线的目标做升级，并保证重复运行幂等。

## 4. 发布前视觉评分与证据

文章发布前必须**打开最终图片和文章标题并逐项人工/视觉审稿**，记录：文章 slug + 当时标题、读者行业、采购用途、画面实际可见主体、场景契合原因、可见水杯情况、内容真实性及授权依据、SHA-256 和审核结论。不得凭文字编造已看图。

按 5 个维度各 1–5 分：**行业/客户匹配、商品/采购用途、商业真实感、不误导与版权、清晰构图**。以后新文章每项不得低于 4，总分至少 **22/25**；否则换图而非降低门槛。机器 CI 负责检查证据、图片尺寸/格式/校验值、错配/重复和审核门禁；**CI 无法凭文件名证明真正的视觉契合，审核人必须实际看图**。

> 站长 10 月 29 日选定的三张**已发布参考图**：仓储员工作业团队（以人物场景体现班组采购，不冒充型号实拍）、机场车站零售选品水瓶货架（以多款实际陈列表现零售用途）、共享办公人员在会议桌旁使用水瓶（体现欢迎礼包/共用工作环境）。参考图按站长选择保留；之后同类主题不得机械重复这些照片，应寻找真正契合各自文章的新画面。

## 5. 必须执行的生产流程（不可跳过）

**选题/正文 → 场景拍摄/选图 → 视觉实际检查 → 记录 `data/blog-cover-editorial-approvals.json` → 运行 `scripts/test_blog_cover_editorial_standard.py` → 文章和图片进入正式 D1/CMS / R2 → 两次干净构建、五语详情/列表/OG 与线上检查 → 发布。**

任何新稿缺审核记录、画面错配、文件校验不一致，**停止 AI 批量发布并换图**；禁止生成一张通用图兜底，禁止使用固定图片池随机分配。作者应修复正式源数据或 D1，而不是修改生成页。若站长在 CMS 自行选择其它图，自动化不能覆盖该选择；这种编辑走管理员视觉审核流程，不通过源数据自动纠错。

审核记录只说明“有真实审核责任人和依据”，不是图像语义识别算法或版权授权的替代品。自动化不能宣称它检测了无法检测的视觉内容。
