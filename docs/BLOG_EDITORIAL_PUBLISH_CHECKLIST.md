# XUYI 博客发布前编辑规范

这是 Blog 新写、重写和发布的唯一编辑门禁。内容与翻译最终写入 D1/CMS，图片写入 R2；不得修改 dist/、线上 HTML 或用浏览器替代正式发布接口。

## 内容结构

- 每篇文章只有一个明确的 B2B 长尾主问题：采购对象、场景、决策问题和读者收益一致。
- 标题、H1、Meta Description、首段、章节、FAQ、矩阵和 CTA 围绕同一问题；优先口语化、问句式或句子式搜索表达。
- 文章必须提供可核验的采购信息：型号、容量（按资料写 ml，必要时附审核后的 oz）、材质、颜色、盖型、MOQ、样品、包装、验收、交期或复购边界。没有来源的数据不写。
- 不允许只替换行业名、颜色或形容词套壳；新增主题必须先读取 D1/CMS 已发布文章，确认搜索意图、受众、漏斗阶段和信息增量，避免关键词蚕食。
- 英文源文至少包含 7 个实质章节、4 个 FAQ、8 个采购检查项、1 个决策矩阵、2–5 个不同且真实的产品详情内链和 2–3 篇文末相关阅读。
- 产品链接必须出现在相关段落中，锚文字与目标语种一致；相关阅读必须真实存在、主题互补、不得自链或重复指向同一 URL。

## 多语言

- 目标语种、发布资格、排序和页面字段从 D1 language_config/CMS 读取，禁止写死语种数量或名称。
- 每个已发布语种都要有独立的 Title、Meta、正文、章节、FAQ、矩阵、产品内链、相关阅读、ALT、按钮和面包屑；不能只翻标题、只拼短摘要或以英文冒充译文。
- 多语正文应与英文源文保持章节和信息对应，但要使用目标语种自然表达，不得把翻译写回静态 HTML 代替 D1。
- 列表页使用同一份 D1 已发布顺序；分页、卡片数量、canonical、hreflang 和 sitemap 必须按当前配置验收。

## 图片门禁

- 先完整读稿，再看最终图片；图片必须直接对应买家、行业、采购场景和文章决策，不得用泛用水杯图凑数。
- 每篇封面独立，不能在同批文章复用；统一为 1200×800、3:2、WebP、30–350 KB，并保留来源、场景、可见主体、使用披露、SHA-256 和人工审核记录。
- 图片不能暗示不存在的客户、订单、认证、工厂流程或实拍事实。真实自然场景和示意图都必须按实际情况描述。
- 先上传并核验 R2，再把 URL 写入 D1；英文和每个已配置语种的详情页、列表卡片、OG/结构化数据都要回读 HTTP 200 和图片 MIME。后台后来选择的图片优先，旧 R2 对象不能凭静态产物判断为未引用。

## 发布顺序

1. 从 D1/CMS 读取当前文章、语言、产品、链接、发布状态和 revision，做主题去重与事实核对。
2. 保存英文草稿和完整多语 payload，逐语种检查章节、长度、FAQ、内链、相关阅读、标题和 Meta。
3. 记录并审核三张独立封面，压缩后上传 R2，按 SHA 和 URL 验证。
4. 使用 /api/admin/blog-batch 写入 D1；人工走正式后台，AI/脚本走 HTTPS API。AI 不操作浏览器、不使用日期专用脚本、不重复 POST。
5. 读取 D1 回执，确认文章数、翻译数、列表卡片数、发布状态和 revision。
6. 通过标准构建与 CI，至少两次干净构建；部署后核验所有配置语种详情页、列表分页、图片、内链、相关阅读、canonical/hreflang、sitemap 和 build-meta.json/D1 revision 一致。

## 失败处理

- R2 或 D1 响应超时/不明确：先只读查询对象、记录和 revision，确认未写入后才重试；禁止盲目重复 POST。
- D1/R2 已写入但构建失败：保留正式数据，修复模板、测试或构建输入后重新部署，不重复写入内容。
- 列表、图片、语言或正文异常：修复 D1/CMS、共享模板或渲染器，禁止直接改生成 HTML。
- 没有完整的 D1/R2、CI、revision、线上 URL 证据，只能标记“待验证”，不能报告“已发布”。

## 主题防重复登记

新文章发布前至少记录 slug、intent、audience、funnelStage、primaryKeyword、coveredQuestions、evidenceSources、supportingLinks、canonicalRole 和 lastReviewed。已有文章只做审核，不自动删除、合并、改 URL、canonical 或发布日期；需要整合必须另行取得明确授权并准备可回滚方案。
