# XUYI 仓库维护与真源地图

更新时间：2026-11-08

这份文档是仓库整理后的当前维护入口。历史日期记录只用于审计和回放，不替代本文件、AGENTS.md、PROJECT_CHANGE_POLICY.md、项目圣经当前规则或 D1/CMS 当前值。

## 一、哪些内容属于正式源

- 业务产品、Blog、评价、翻译、页面 SEO、发布状态和语言配置：以 Cloudflare D1/CMS 为准。
- 产品、导航、页面路由和可编辑字段：以 D1 配置、受控源数据和共享渲染器为准；不得从静态 HTML、旧 README 或固定数量反推当前状态。
- 图片和媒体引用：原始对象在 R2，引用路径、ALT、语言和审核关系由 D1/CMS 管理。
- 页面结构、公共组件和样式：以 `templates/site/`、共享渲染器和受控 CSS/JS 为准。
- 构建发布状态：以 GitHub Actions 结果、生产 `build-meta.json`、D1 publish revision 和线上回读为准。

## 二、目录职责

- `functions/`：Pages Functions、Admin API、D1/R2 读写和必要的动态回退。不能把普通内容发布改成每次请求临时拼装。
- `templates/site/`：共享 HTML 结构；不能为单个生成页面复制一套模板。
- `data/`：源目录、审核基线、结构化配置和可复现测试 fixture。只在代码或测试明确引用时才属于活动输入。
- `scripts/`：构建、测试、快照、审计和受控发布工具。标准入口见 `scripts/README.md`。
- `docs/`：当前操作说明、验收清单和媒体/文章标准。日期批次说明保留作审计，不是日常入口。
- `项目圣经/`：系统架构、发布规则和历史记录。当前规则优先，旧日期记录不得覆盖当前 D1/CMS 事实。
- 根目录 Python/模板/静态快照：属于现有构建兼容源；不可手工编辑生成 HTML，也不能把根目录快照当成线上数据源。

## 三、标准操作入口

1. 读取 `AGENTS.md`、`PROJECT_CHANGE_POLICY.md` 和当前项目圣经。
2. 确认字段所有者与 D1 当前值；业务修改使用正式 API/CMS，图片先写 R2 再写 D1 引用。
3. 使用 `scripts/preflight.py`、`scripts/build_release.py`、`scripts/test_release.py` 和相关回归脚本。
4. 构建至少验证两次，确认后台编辑优先、重复执行幂等、语言/产品/文章增长不被旧数量卡住。
5. CI 通过后才部署；生产状态以 build-meta、publish revision 和线上路由回读为准。

AI、localGPT、脚本和自动化发布默认 API-only；人工可以使用正式后台。任何不明确费用、额度或计费的 API 禁止调用。不得直接改 `dist/`、线上 HTML、Pages 成品或 R2 缓存。

## 四、清理规则

- 删除前先做仓库内引用检查，确认不被构建、工作流、函数、测试、数据加载器或文档入口使用。
- 只清理明确无引用的一次性请求、重试 payload、临时日志和旧迁移痕迹；不得用“看起来旧”作为删除业务数据的理由。
- 已发布产品、Blog、评价、翻译、R2 对象、D1 记录和可追溯的审核材料不得因整理仓库而删除。
- 日期脚本若仍被 CI、构建或回放流程引用，继续保留并标注为历史回放；不得复制为新的日常发布入口。
- 新增说明应更新当前入口文档；不要继续新增只记录一次操作、没有真源和验收结论的散落说明。

## 五、当前状态判定

产品数量、语言数量、分类数量、路由数量、分页数量和公开状态均不在本文件固定。需要核对时读取 D1/config、快照 manifest、生产 build-meta 和线上页面；历史记录中的数量只代表当时的审计时点。
