# 2026-10-10｜R2 图库直接换图与原路径回滚

## 业务目的

用户希望在现有后台「R2 图片管理与引用检查」中直接上传新图片，替换已经被网站引用的低清 R2 图片，无须手动逐页替换 URL。仅修改 XUYI 独立项目，不触及无关项目业务、原有网站产品型号词批量导入或第二个 R2 型号溢出桶。

## 新增功能

- 每张 R2 图片增加「上传新图替换（原地址）」按钮，包括 `product/page/shared` 上传管理分类，和旧 `ppt/excel/group/capability/gallery/blog` 图片分类。
- 新弹窗左右并列展示原图、新图，用户自行检查是否为**相同型号/相同适用栏目**、瓶盖、颜色、Logo、工厂实拍与图片授权；必须勾选确认后才能执行。没有自动产品型号视觉识别，不冒充系统能证明同型号。
- 浏览器支持 PNG/JPEG/WebP，若现有 URL 为 WebP，会在浏览器端转换为 WebP，再上传；目标 URL 路径和扩展名保持不变。服务器再次验证文件头、MIME、真实像素宽高，且新图宽高不得低于当前图。
- 替换前校验该对象实际存在、检查 R2 ETag 防止并发覆盖；后台身份验证严格使用 `authorizeAdminRequest`，Cloudflare CI token 不可使用。
- **先备份并验证旧图再覆盖原 URL**，旧图置于同一 XUYI R2 桶的私有 `site-image-versions/<kind>/<filename>/<timestamp-uuid>`，不通过 `/media/` 公共代理公开。
- 备份历史可在管理弹窗查看，点击「恢复此版本」会再次先备份当前图片，再将指定旧版写回原位置，从而保留反向恢复机会。任何备份/校验失败应阻止覆盖，不破坏原图片。
- 现有的**删除保护没有改变**：旧 PPT、Excel 等分类只能替换、不能直接删除；上传管理类图片须先检查静态正式网站+D1所有引用，未使用才可删除。媒体库图片重命名、另一个 R2 型号桶的 manifest 和版本控制均不由替换接口修改。
- 后端 API：`GET /api/admin/media-replace?kind=...&filename=...` 读历史，`PUT` 上传同路径替换，`POST {action:"restore",version,...}` 回滚。
- `functions/media/[kind]/[filename].js` 新响应的浏览器缓存时间从一小时缩短到五分钟；**此前已经缓存的旧响应仍可能保留至原一小时 TTL 到期**，但使用 `?r2preview=...` 可主动查看新图片，不代表所有访问者瞬时更新。
- 该功能仅覆盖 R2 代理路径 `/media/...`。首页此次高清整改采用的 GitHub 静态 `/assets/curated-hd/...` **不属于 R2**，需走后台内容重构或 Pages 静态资产部署，不能通过这个模块操作。

## 安全与验收

- `scripts/test_media_replacement.mjs` 使用本地模拟 R2 执行 19 项检查：后台权限、图像真实尺寸、格式、ETag 冲突、低清拦截、未勾选确认、备份失败阻止覆盖、已引用路径保持同名、历史版本、恢复并备份新图、合法旧 PPT 图片、非法路径等。**不向正式 R2 写文件**。
- `scripts/test_media_library.mjs` 的静态+D1 引用安全删除测试继续执行，`test_release.py`、四语页面和 R2 溢出测试也需要持续通过。
- 本次无任何实际产品图被覆盖，没有真实更改或删除线上用户文件。首次实用应由运营人员在后台选取明确已核实的低清图，并检查原图/新图预览。
