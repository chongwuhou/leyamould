# 2026-10-10｜旭一全站真实浏览器复检与 ALT 后台授权修复

## 实际检查范围与结论

- 对真实生产站抽查 English/ES/PT/RU/TR 首页、商品目录、型号 2501、分类、Blog、联系与 FAQ，桌面 1366px 和手机 390px 视口共 26 次访问：HTTP 200、无 JS pageerror、无横向溢出、ALT 属性均完整。
- 直接扫描静态发布包的所有内容 `index.html` 并汇总真实图片 `src`：138 个不同图片 URL，逐个从 `https://xuyibottles.com` 请求，全部返回 HTTP 200 且 `Content-Type` 是图片。页面共用的 `href="#"` 是带独立点击处理的 Back to Top，不是产品页坏链。
- 手机 390px 视口依次实际点击五种语言的菜单按钮，`aria-expanded` 均从 `false` 变成 `true`；同时检查产品目录 390、768、1536px 布局。
- **实际复现的功能 Bug**：此前 `assets/admin-media.js` 内请求包装器 `fetch(path,{headers:{authorization,...options.headers},cache:'no-store',...options})` 会因末尾 `...options` 再次覆盖 `headers`。R2 上传使用 FormData 未指定 `headers` 因而看似正常，而「保存图片 ALT」传入 `headers:{'content-type':'application/json'}` 后，**管理员 Bearer 认证被意外丢失**，服务器返回 HTTP 401。用实际运行中的浏览器请求包装器单独执行，修复前观测到 GET 含 `authorization`，JSON ALT 修改仅有 `content-type`、`AUTH_PRESERVED false`。
- 修复为 `fetch(path,{...options,cache:'no-store',headers:{...options.headers,authorization:'Bearer '+token()}})`。确保调用方的 POST/JSON/multipart 等参数保留，但只有可信会话里的令牌能够决定 `authorization`。新增 `scripts/test_admin_media_auth.mjs`：直接运行真实脚本及 mock fetch，强制测试 GET、JSON ALT 保存、FormData 上传全都保留授权头，加入 GitHub Actions 发布门禁。
- **第二个实际复现 Bug（五语目录筛选、分页全部失效）**：`assets/site.js` 正确在首屏将 85 个商品中的 67 个设为 `hidden=true`，但是作者 CSS 的 `display:block` 覆盖了浏览器自带的 `[hidden]{display:none}`。在真实生产 `/products/` 输入 `2501` 后计数为 `1 models`，屏幕却仍显示 85 张卡片。通过 Chrome 运行时实测 `getComputedStyle(hiddenCard).display === 'block'`。现由全站基础样式强制 `[hidden]{display:none!important}` 保证搜索、分类、分页以及其它原生 hidden 控件符合行为预期，新增 `scripts/test_catalog_visibility.py` CI 门禁。
- 在真实 390px Chrome 中按最新 CSS 注入验证五种语言完整交互：首页 18/85 个；搜索 `2501` 只显示 1 个；无匹配显示 0 个；分页第 2 页显示 18 个；均无横向溢出。此修正纯粹修复显示逻辑，不改变商品总量、发布内容和 URL。
- 无正式用户数据写入：未向真实 D1、R2 创建测试图片/商品，不发送模拟询盘；所有交互验证和更改都在本地 mock/browser 无副作用进行。

## 以后不可回退

1. 后台 API 封装必须先展开请求选项，再最终组合身份验证头；不能把 `...options` 放在配置的最后，使 `options.headers` 覆盖登录令牌。
2. 任何新增「JSON POST 保存图片 ALT」都要走 `scripts/test_admin_media_auth.mjs`，不能只测 `functions/api/admin/media.js` 的 mock 服务器行为；原旧测试没有覆盖浏览器发送的实际 Header。
3. `hidden` 原生属性必须有对应基础 CSS 优先级，不得被卡片/面板自身 display 声明抵消。删除或修改 `[hidden]{display:none!important}` 必须在五语商品搜索、分页和动态 tab 浏览器交互通过后才能发布。
4. 更动语言 Header、商品列表和 CSS 必须补真实的五语手机/桌面交互测试。
5. Cloudflare 历史三个旧源码缓存 `/build.py`、`/site_renderer.py`、`/data/products.json` 仍为独立安全阻断，必须由具有 Zone 缓存权限的操作者精确清理并复测 404/410 后，才能审批 `indexingApproved=true`。

**这轮审核不会擅自开放 Google/Yandex/Bing/百度收录**，所有实际网页继续 obey `robots.txt` 和 `noindex`。
