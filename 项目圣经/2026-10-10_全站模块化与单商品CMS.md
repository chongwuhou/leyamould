# 2026-10-10｜全站通用模板与单商品 CMS 优化

## 目的与范围

用户明确要求的是 **整个 XUYI 站点“一处维护、多处复用、简单高效实用”**，不是继续照搬无关项目的其他行业批量型号架构。

保留：Cloudflare Pages 静态预渲染、D1 内容真源、R2 素材、原 URL、五语审核、SEO 的 noindex 发布门禁、Github 定时发布及恢复机制。**不做**水杯证据审核模块、不恢复型号批量导入、不复制无关项目实际业务数据，不为模块化引入 React/WordPress/新数据库。

## 本轮全站复用改造

| 模块 / 真源 | 实现 | 一处修改的结果 |
|---|---|---|
| 页面 HEAD / SEO meta / icon / site.js | `templates/site/head.html` | 所有英文生成页统一页头，不再在 Python 中拼超长 HTML |
| 头部、导航、移动菜单 | `templates/site/header.html` + `data/site-navigation-defaults.json` + D1 `site_navigation` | 同一个菜单数据渲染桌面/移动端；D1 可修改排序与链接；原四列设计不变 |
| 页脚和侧边联系入口 | `templates/site/footer.html`、`sidebar.html` + D1 Brand/Contacts | 一处更新，全站公共位置复用 |
| 联系表单字段 | `templates/site/contact-form.html` | 不再把整段表单写在 `build.py`；四语联系页继续复用既有翻译+表单注入机制 |
| 统一章节标题 | `templates/site/section-heading.html` | 首页、目录、服务页复用 `sec()` |
| 通用特点/利益点卡片 | `templates/site/product-benefit.html` | 首页、产品详情、买家介绍复用同样结构 |
| 下单/合作步骤卡片 | `templates/site/process-step.html` | 同样的 `<div class=step>` 结构从主页渲染代码移到模板 |
| 商品卡、目录/分类、详情图库、FAQ | 原 `product-card`、`product-overview`、`product-thumbnails`、`product-spec`、`faq-list` 等 | 新老商品共用，无需复制完整详情 HTML |
| 商品分类菜单内容 | `data/site-navigation-defaults.json` | 四栏栏目、图片、链接改同一个配置，不在页面代码里硬编码两套 |

本轮从 **18 个实用模板扩展至 22 个**，依旧完整静态 HTML 输出；既有 `home/listing/content/static` 是内容插槽，不假称整个网站都是可视化区块编辑器。下一轮可按业务需要把重要首页 section 做成更细独立内容块，但不为“模块数”而增加维护负担。

## 新功能：后台手动新增一个商品

「网站内容、导航、SEO 管理」中新加 **“+ 单个新商品”**，遵守此前“不做大批量型号导入”的决定：

1. 选择水杯类别，填入唯一英文 slug、商品名称、材料、容量、颜色、包装、说明、R2 主图、SEO 标题与描述。
2. **保存草稿：只写 D1，不生成公开页面。** 下次可从已保存商品中选取继续编辑。
3. **核实后发布**：要求非空名称/材质/容量/说明/R2 图片，服务端检查真实 R2 对象存在，验证不与旧 85 个商品型号冲突；确认发布后 D1 revision 自动增加，沿用 GitHub Actions 定时发布流程。
4. 构建端从 D1 的 `xuyi_product_content` 已发布项增补 `SERIES`。自动参与 `/products/` 目录、类别列表、现有详情模板、唯一 canonical、结构化数据、Sitemap 与 R2 文件索引。没有手工复制 HTML。
5. **四语仍须分别审核**：原有「多语言正式页面」允许为已经发布的单商品新路由录入审核后译文；没有审核时不会自动发布同名假译文。
6. 修改已发布单商品时，仍可选择草稿/正式状态。将商品重新标记草稿会在下次发布中撤下静态商品页，需注意外部既有引用可能成为 404，后续可再加“下架→301 跳转”业务流程。

**职责明确**：
- `functions/_shared/new-product.js`：后台字段/型号和 R2 路径校验；
- `functions/api/admin/product-content.js`：D1 保存与发布权限（新建仅真实管理员，不给 GitHub CI Token）；
- `catalog_extensions.py`：英文构建只接受已发布新商品，验证类别与字段后并入原有 SERIES；
- `site_renderer.py` + `product_content.py`：沿用现有产品卡/详情、SEO；新商品不冒称“原 Excel 目录数据”；
- `functions/api/admin/page-translations.js`：仅允许新增商品已发布英文页后提交该路由四语审核稿；
- `assets/admin-content.js`：一份后台 UI，不开单独的复杂内容管理平台。

## 测试与边界

- `scripts/test_single_product_module.py`：在内存临时构造新商品，验证卡片、详情、SEO、分类、型号冲突与清理。
- `scripts/test_single_product_api.mjs`：在模拟 D1、R2 中验证真实管理员、草稿、R2 不存在拦截、已发布页面数据存储，不写线上 D1。
- `scripts/test_single_product_build.py`：用临时本地快照建一个 **完全虚构、不会上线的 QA 商品**；确认英文页与仅有的西语审核页面、canonical、Sitemap，然后恢复原快照和全部静态输出；首次本地已验收通过。此项作为手动 E2E，不在每次定时 GitHub 发布里额外构建两次。
- `scripts/test_shared_templates.py`：验证 22 个模板、联系表单、章节标题、步骤、导航。
- 当前没有真实新增商品，也没有把测试数据写入生产 D1。后续真实添加商品仍需运营人员核对材质、容量、照片；不会凭 AI 猜测。

## 仍需区分

- 本轮全站复用目标是**代码与内容模块化**，不是允许用户随意拖动任意 HTML 组件。已有的首页、资源页、公司页在 Python 模块中组合，底层共享标签逐步抽出；如需拖拽页面编辑器，应另行明确需求，避免当前后台难维护。
- 产品图片仍可从 R2 07 媒体管理上传、按原 URL 替换、恢复旧版。静态 `/assets/` 不通过 R2 图片界面变更。
- 网站仍保持 noindex，等用户确认 SEO 上线；SMTP 配置、旧 CDN 缓存安全遗留独立处理。
