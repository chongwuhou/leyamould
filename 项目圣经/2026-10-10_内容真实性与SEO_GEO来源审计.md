# 2026-10-10｜旭一水杯站内容真实性、SEO/GEO 与可核实来源优化

## 本轮用户要求和范围

- 不增加空洞的统一模板化内容；优先核查其他业务页与知识文章。
- 保留原来的结构化商详（图集、完整产品参数、型号、FAQ、询价入口、关联型号）。只允许在产品证据确凿后按需补充，**本轮没有提交对 85 个商详正文的重写**。
- 由真实原始来源支持通用采购法规建议；任何权威法规本身均不意味着旭一已经获得报告、认证或符合标准。
- 不擅自解除 noindex；外语 D1 审核版本不自动重译或改写，不引入德玛隆的后台/数据库/业务内容。

## 审计发现

1. 16 篇已有 Blog 具备主题区别和较完善的文章骨架，但没有可点击的外部**一手来源**，材料、BPA、儿童用品及检验方法的解释缺少出处。将引用加在最相关的 **6 篇**，而不是所有文章无差别堆积“权威链接”。
2. About/Manufacturing/Quality Control 的商务表述有真实目录和流程，但原本缺少实际货号/具体交接物/食品接触材料标准三类较硬的信息。针对每页独立增加不同的可信补充。
3. 已发布 D1 的 `pageBodies` 可能覆盖 Python 页面生成正文。只改 `build.py` 或 `resource_pages.py` 而不调整最终渲染可能导致已开发内容正式发布后缺失。因此由 `editorial_support.py` 通过 `site_renderer.build_url` 在 D1 管理正文**之后**追加限定路径的独特来源块，且防止重复插入；CMS 原正文与权限不变。
   - **上线后的二次复核**发现部分 Blog 同样存在 D1 正文覆盖：正式 `main` 发布了初版，但六篇文章的来源区没有进入最终页面。进一步把 `blog_editorial.render_primary_evidence` 作为单一生成入口；`site_renderer.build_url` 对相应 Blog 在 D1 覆盖之后检查并补入该引用区，保留原文章正文。必须以第二次线上逐篇核对为准。
   - **最终根因另有一层：**线上 `/blog/*` 在 Cloudflare Pages Functions 的 `functions/blog/[[path]].js` 中优先读取 `xuyi_blog_posts`，通过 `functions/_shared/blog-cms.js` 动态组合 HTML，静态页面的更新并不是最终用户看到的页面；定点修复必须在此动态渲染器进行。这次已增加 JSON 来源导入、每篇唯一来源段落、动态 BlogPosting `citation` 和仅影响这 6 篇的内容修订日期。新增 `scripts/test_blog_dynamic_evidence.mjs` 验证这六条动态 D1 路径对应的正文与来源匹配。不覆盖或重写 D1 Blog 业务员原文。
4. 商品源图册有未经人工审核字段，特别是 2506 的容量疑点。不要用未经验证的型号参数、测试或安全等级来补 SEO 字数。
5. 遵照 Google Search Central 的 people-first 原则：按采购意图增加直接答案、可行动的核对点、与原始来源的对应关系，拒绝为了 GEO 机械加“AI 友好”堆词和复制相似段落。

## 技术实现和后续

- `data/editorial-evidence.json`：每篇文章选用独有的核实事实、采购核对建议和一手来源，不做模板填充。
- `blog_editorial.py`：6 篇文章显示可点击出处；BlogPosting JSON-LD 按本篇引用追加 `citation`；确实更新的文章才更新日期。
- `editorial_support.py`：只对三条重点企业/质检路线追加不同实质内容，D1 管理正文原样保留。
- `scripts/test_editorial_evidence.py` 加入 GitHub 发布门禁，验证来源 URL、页面落地、新版显示、不会丢失原有商品规格。
- 下一批等待公司真实素材：自有车间/工艺流程照片、精确型号 BOM、适用市场检测文件、客户要求与样品/包装前后对比。没有素材前，不虚构生产数据、合规或订单案例。
