# 2026-10-10｜XUYI 多搜索引擎上线门禁与提交流程

## 一、当前真实状态

- 正式主域为 `https://xuyibottles.com/`，首页英文；ES/PT/RU/TR 为独立审核语言。
- 675 个公开内容 URL 已在 `sitemap.xml` 中，正式站均暂时 `noindex`，`robots.txt` 目前为 `Disallow: /`。尚未提交 Google / Bing / Yandex / 百度。本文件不是已完成收录的证明。
- 85 型号、425 个五语商详页已发布。最终检查 Title、Description、H1、canonical、hreflang、x-default、Schema 及内链均通过；部分较长外语 Title/Description 是编辑建议，不是 Google 固定字符违规。
- 三个早期 Cloudflare Zone 缓存路径 `/build.py`、`/site_renderer.py`、`/data/products.json` 仍无查询参数时 HTTP 200。**必须先有权限清理，并在原 URL 上确认 404/410；之后才能批准收录。**

## 二、不同搜索引擎的正确方式

| 搜索引擎 | 站长平台 | 经过验证后的正式提交方式 |
|---|---|---|
| Google | https://search.google.com/search-console | DNS 验证 xuyibottles.com 域名属性；在 Sitemaps 添加 `https://xuyibottles.com/sitemap.xml`，GSC URL Inspection 抽查五语首页、商品、Blog。GSC API 需要经过授权；一般商品页**不能**使用 Google Indexing API 强推。 |
| Bing（亦用于 Microsoft/Copilot 检索） | https://www.bing.com/webmasters/ | 从 GSC 导入已验证域名或独立验证；添加 sitemap，随后通过 IndexNow 自动通知新增及更新 URL。 |
| Yandex | https://webmaster.yandex.com/ | 验证站点；添加 sitemap；IndexNow 也能传递新增/更新 URL。 |
| 百度 | https://ziyuan.baidu.com/ | 完成独立站点验证，在「资源提交／普通收录」提交**单一 URL 列表型 XML** `/sitemap.xml`。API 主动推送必须使用百度平台单独颁发的 token；**IndexNow 不代替百度**。 |
| Naver、Seznam 等 | 各自站长平台 | IndexNow 参与平台之间会共享 URL 通知；仍可独立添加验证站点与 sitemap。 |

## 三、项目已实现的自动提交功能（先关闭）

1. `scripts/search_submission.py` 读取真实 sitemap 的 675 个 canonical URL，并对最终 HTML 建立 `dist/search-submission-manifest.json` 内容指纹（非虚假 lastmod），用来区分今后的新页面和实际修改页面；动态 D1 Blog 随 D1 发布 revision 变化也更新通知指纹。
2. `scripts/build_release.py` 每次构建生成指纹清单。只有 `deployment/site.config.json → indexingApproved=true` 且 GitHub Actions 已设置项目独立的 `XUYI_INDEXNOW_KEY` 时，才会在网站根目录生成指定密钥验证 TXT 文件。禁止索引时不会输出 TXT。
3. GitHub Actions 部署前抓取上一个版本的公开指纹文件和 robots；部署后**先验证正式生产版本成功、robots 已允许抓取、首页无 noindex 且密钥 TXT 文件能访问**，再向 `https://api.indexnow.org/indexnow` 提交新/更新的 canonical URL。首次从禁止抓取改为可抓取时提交完整 sitemap URL 集，之后只推送内容指纹改变的 URL。
4. `scripts/preindex_security_gate.py`：只要准备开放收录、旧源码缓存有任意 HTTP 200，GitHub 构建在部署前直接失败。这样不会因为以后某次升级绕过安全阻断。
5. 没有 GSC 站点所有权及令牌的情况下，不会声称已将 sitemap 提交给 Google；没有百度站点验证及主动推送 token，也不可能合法提交百度 API。
6. 首页 Banner HTTP 预加载头现在**只写到五种已发布语言的首页**，只加载当前第一张 Banner 图片。其余商品和文章不再浪费流量预加载旧版四张 Banner。

## 四、实际开放前的操作顺序

1. 拥有 Cloudflare Zone 缓存权限者从 Caching → Purge Cache → Custom Purge，精准清理 `https://xuyibottles.com/build.py`、`/site_renderer.py`、`/data/products.json`，同时按实际 www 解析清理其对应域名版本。必须使用无 query 的原 URL 验证 404 或 410，不能认为发布新构建等于 CDN 缓存已清理。
2. 确认 GSC、Bing、Yandex、百度的平台帐号是否已验证 xuyibottles.com；未验证时完成平台规定的 DNS、HTML 文件或 meta 标签所有权验证。**不要虚构 token 或直接往公开代码提交私密令牌。**
3. 在 GitHub 私有仓库的 Actions Secrets 新建 `XUYI_INDEXNOW_KEY`（随机且符合 IndexNow 规则，建议 32 位十六进制），使发布流程能创建根目录密钥 TXT。需要百度自动主动推送或 Google Search Console API 时，再独立确认帐号授权方式与配额。
4. 在清理旧缓存、确认内容和平台验证后，由业务负责人明确批准将 `indexingApproved` 改为 true。只有此项变更才令正式站的 meta robots、Blog HTTP 响应头、robots.txt 和首页 Google/Bing 索引开放。
5. GitHub Actions 从 D1 拉取完整生产快照、构建、执行原有 675 页和新增多搜索引擎发布测试。安全门禁通过才部署；然后 IndexNow 通知参与引擎。到 GSC、Bing、Yandex、百度后台分别提交 `https://xuyibottles.com/sitemap.xml` 并保存首次提交及索引反馈。
6. 24–72 小时后在各搜索平台检查 Sitemap 读取、已发现 URL、规范页面、语言对应、抓取异常和软 404；收录和排名都不能由“已提交”保证。对被排除的 URL 检查具体原因，不盲目重复推送或制造关键词页面。

## 五、未来升级时必须记住

- **IndexNow 不包含 Google 和百度**，不能把单一接口误称为“向所有搜索引擎提交”。
- `robots.txt` 与 meta robots、HTTP `X-Robots-Tag` 都必须同时正确；有任何一处仍 noindex 或完全 Disallow 都不能开启推送。
- 只提交自己域名的真实 canonical 页面；不推送管理员、草稿、跳转、图片或未审核语言 URL。R2 溢出的真实公开商详同样由发布 manifest 识别，不能漏掉。
- 不编造 `lastmod`、热度、评分、产品认证、材料证据等 GEO 信息。
- CI 必须保留 `scripts/test_search_submission.py`、`scripts/preindex_security_gate.py` 和 `scripts/test_seo_multilingual_launch.py`。新增第六语种及新增商品仍由实际译文和 sitemap 管理。

**本次最终验收未执行任何搜索引擎提交，也未打开收录开关。**
