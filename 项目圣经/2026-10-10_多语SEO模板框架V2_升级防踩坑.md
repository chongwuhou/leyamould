# 旭一网站多语言 SEO/GEO 模板框架 V2｜升级规范与防踩坑（2026-10-10）

## 此次根因

过去的 ES/PT/RU/TR 语言白名单被复制到 Python 构建器、共用 Header、Banner 管理、前端 JS、后台 D1 翻译保存接口、R2 型号页溢出处理和测试脚本。即使五种语言当时通过检查，新增第六种语言仍可能出现页面内容已经发布、却缺少 canonical/hreflang、OG、本地化 JSON-LD、首页 Banner 或 R2 产品展示的问题。只“修五种语言”无法根治。

## V2 的唯一真源与组件关系

- **语言身份/URL 前缀**：D1 的 `site_state.language_config`（由 `/api/admin/site-settings` 管理），需满足 `enabled=true` 和 `publishReady=true`；只读 build-snapshot 带到本次正式构建。路径和语言码都经严格验证。
- **默认语言**：`deployment/site.config.json` 保持 `defaultLocale=en`，英文首页为根 URL。任何改默认语言 / sourceLocale 的行为现在由框架与后台共同拒绝；**这不是切换一个后台单选框就能完成的事情**，必须另做迁移方案与 301。
- **构建发布注册表**：`locale_registry.py` 是 Python 模板侧唯一入口（`approved_locales`）；内容是否实际可公开还需验证 D1 已审核的该路由正文，不做伪外语页。
- **自动生成页面清单**：`dist/locale-manifest.json` 包含当前语言、路径前缀和真实审核页面列表，供 SEO 发布验收与溢出规划使用。它随构建重新生成，不是手工编辑文件。
- **页面元信息**：`scripts/render_locales.py` 只对审核路由生成自指 canonical、该语言的 Title/Description/OG、正确语言的 JSON-LD；不再把英文 BlogPosting、Service、Product 等结构化数据错误复制给外语。每组实际存在的页面才生成双向 hreflang 和英文 `x-default`；未审核页面不在 hreflang/sitemap。
- **共用 Header 与语言切换**：`site_renderer.py` 生成语言选项；浏览器 `assets/site-settings.js` 使用 D1 语言列表 + 当前 HTML lang + 该页已有 hreflang 的交集，只提供真正存在的对应 URL，不用固定五语正则。
- **Banner 管理**：`home_banner_config.py` 按注册表校验所发布语言的 3 张 Banner；`functions/_shared/home-banners.js` 和后台保存接口保留尚未发布新语言的草稿，并强制所有已发布语言都有完整五个字段。不会因编辑一次 Banner 无声丢掉未来语言字段。
- **后台翻译**：`functions/api/admin/page-translations.js` 从 D1 语言配置核验可编辑语种，不再写死 ES/PT/RU/TR。可先给尚未 publishReady 的语言编写、审核译文，再改发布标志。
- **D1 动态 Blog**：沿用真实的每篇文章静态 HEAD，不能使用 /blog/ 目录页 hreflang。D1-only 新博客不凭空声称拥有外语翻译；HTTP X-Robots-Tag 遵守统一收录批准开关。
- **R2 溢出**：`scripts/plan_model_overflow.py` 和 `functions/_shared/model-overflow.js` 按实际存在且审核的语言商品 URL 路由工作；新语言不能在接近 Pages 文件数限制时突然丢失商品页。
- **搜索收录开关**：`deployment/site.config.json → site.indexingApproved` 是唯一发布批准标志。目前 **false**。新增语种不允许自行开索引。

## 添加新语种的正确顺序

1. **先添加语言，保持 publishReady=false**。在 D1 语言设置登记合法 BCP47 代码、原生显示名称和独立 URL 前缀（例如 `fr` → `/fr/`）。不能占用 `/admin/`、`/api/`、`/products/`、`/collections/` 等保留路径。不要改默认英文根主页。
2. 在源代码中**准备真实人工审核的语言资源**：`data/ui-translations.json`、`data/runtime-ui-translations.json`、`data/contact-form-translations.json`。UI 必须覆盖现有共享导航所用键，避免英文标签漏出。不要直接复制西语文案假称法语；测试用模拟字串绝不可带到生产。
3. 在后台把 3 张 Banner 的新语种标题、强调词、介绍、图片 ALT 和 CTA 补全并保存；所有语言继续共用原有 3 张图片和安全跳转。
4. 使用 D1 `page-translations` 编辑器先审核新语言的**首页**，再逐一审核目录、品类、产品、About、能力、Contact、Privacy、FAQ 和相关文章。只有完整审核过的 URL 才应出现该语言版本。不能通过机器翻译直接冒充终审。
5. 审核完成后再将语言设为 `enabled=true,publishReady=true`。正式构建检查完整语言资源、Banner、已审核首页及路径冲突；不满足条件就 **失败并保留上一版生产站**，不会生成半成品页面。其他未翻译的 URL 仍可使用英文后备链接，但不能伪造 hreflang。
6. GitHub CI 必须运行 `scripts/test_future_locale_framework.py`、`scripts/test_future_locale_runtime.mjs`、`scripts/test_seo_multilingual_launch.py`、`scripts/test_localized_release.py`、`scripts/test_shared_chrome_i18n.py`、`scripts/test_home_banners.py`、R2 Overflow 测试与原有整站回归；最后核实正式站新语种首页 canonical、href、JSON-LD、导航选择器、Banner、Blog 和 sitemap。
7. 如果任一步失败，先保持新语言 `publishReady=false`，检查 D1 翻译/资源/Builder 报错；**不要绕开测试、不要用自动英文兜底伪装外语**，更不可把外语 canonical 统一重定向到英文。

## 自动验收覆盖

- `scripts/test_future_locale_framework.py`：只在临时目录合成“第六语种”页面；先验证缺 UI/Banner 阻止发布，再验证审核首页、路由、hreflang、x-default、外语 JSON-LD、OG、sitemap 和未审核 URL 不发布。**没有向生产 D1 写入法语或任何新语言。**
- `scripts/test_future_locale_runtime.mjs`：新增语种的 Banner 保存保持所有版本；缺单张翻译就失败；新语种 R2 产品路由能识别，不会接受任意未列出的实际 HTML。
- `scripts/test_seo_multilingual_launch.py`：从真实 `locale-manifest.json` 而不是固定五语数组读取语言，审核页面 Title/Description 无缺失、无重复、canonical、自引用、互相 hreflang、x-default、JSON-LD 和 Sitemap 覆盖。混合 R2 模式还验证被移出的 HTML，而不是误认为商品消失。
- 后端通过 D1 已配置语种验证语言翻译和 Banner 保存；V2 构建保持当前原始页面、85 个结构化商品、已审批 D1 内容和既有四种外语页面。

## 明确不可混淆的遗留问题

1. **上线安全未完成**：旧版 `/build.py`、`/site_renderer.py`、`/data/products.json` 的裸 URL 曾仍返回 200，是 Cloudflare Zone 的老缓存问题。这个多语 SEO V2 框架改造不能代替有权限管理员的 Custom Purge。实际开放索引前必须核验原始路径 404。
2. **SEO/GEO 非排名保证**：本次处理的是技术一致性与机器可理解性，不宣称 Google 已收录、不保证搜索或 AI 引用提升。技术通过之后，仍需要真实产品数据、原创案例、准确材料/法规文件和本地化内容终审。
3. **如果要更改默认主页语言**：先设计 URL 迁移、301、历史 canonical、全部 hreflang 与站点地图，并由负责人批准；不要改 `defaultLocale` 或 `sourceLocale` 之后直接发布。

框架版本：`deployment/site.config.json.localizationFrameworkVersion=2`；正式发布包 `build-meta.json.localizationFrameworkVersion=2` 可用于核对线上是否升级。**生产 `indexingApproved=false` 保持不变。**
