# XUYI 统一内容、翻译与媒体发布标准

生效日期：2026-11-05  
级别：P0，适用于人工、AI、localGPT、脚本、GitHub Actions、CMS 管理后台和后续所有自动化。

## 1. 先确定唯一真源

| 内容 | 唯一写入位置 | 禁止作为发布源 |
|---|---|---|
| 产品标题、H1、描述、OG、正文、翻译、博客、评价 | Cloudflare D1 / XUYI CMS 正式记录 | dist、线上 HTML、临时 JSON、一次性 HTML 替换 |
| 图片、封面、ALT 对应媒体 | Cloudflare R2；ALT 和引用关系写入 D1 | 直接替换网页图片地址、把本地文件当线上媒体 |
| 模板、组件、渲染器、回归测试、发布规则 | GitHub 源码 | 直接改生成页面 |
| dist、sitemap、静态页面 | 标准构建产物 | 手工修改后再发布 |

业务数据必须进入 D1；媒体必须先进入 R2，再由 D1 记录引用、ALT、语言和发布版本。源码模板可以在 GitHub 修改，但不能用源码里的临时内容绕过 D1 已有人工值。

## 2. AI 和工具的硬规则

- AI 只能做草稿、翻译初稿、SEO 组合建议、去重、格式整理、风险筛查和审计；不能凭空补造容量、材质、认证、MOQ、工厂证据、客户体验、评价或图片事实。
- AI 生成的产品、博客、翻译和评价，必须先进入“待审核”状态；审核通过后才能条件写入 D1。评价必须有可核验来源、准确 SKU、fingerprint、source 和审核状态。
- 工具默认只读或 dry-run。实际写入必须使用现有、已鉴权的 XUYI D1/CMS 或 R2 管理入口，并明确记录操作者、批次、时间、旧值摘要、新值摘要和 publish revision。
- 禁止脚本、插件、自动化或 AI 直接写 dist、线上 HTML、Cloudflare Pages 成品或 R2 缓存来冒充发布。禁止用旧静态回退表覆盖后台编辑。
- 工具必须幂等：重复运行不重复插入、不删除已有数据、不回退人工修改；更新必须按资源 ID、语言、SKU 和旧值/指纹条件写入。条件不满足就停止并报告，不强制覆盖。
- 任何计费、额度、试用赠金或费用不明确的 API 禁止使用；只用项目已批准且可确认安全的连接。

## 3. 产品、博客、评价和图片发布顺序

1. 读取 D1/CMS 当前记录、字段所有者和 publish revision，先做可恢复快照。
2. 读取真实产品/文章/评价来源，生成待审核草稿；翻译必须逐语言检查，不用英文正文自动充当译文。
3. 人工确认事实、SEO、五语、链接和图片场景。博客正文放 2–5 个真实相关产品链接，结尾人工选择 2–3 篇相关阅读。
4. 新图片先校验来源、尺寸、格式、SHA-256 和场景，再上传 R2 新对象；R2 成功后才写 D1 图片路径、ALT、语言和引用。原对象不覆盖、不删除，除非通过引用检查和可恢复流程。
5. 对 D1 做条件写入并 bump publish revision；失败或版本冲突时停止，不自动重试覆盖。
6. 由标准构建从 D1 + R2 + GitHub 模板生成 dist；必须完成两次干净构建、回归测试和 CMS owner-edit 保留测试。
7. 通过 CI 后才部署；部署后核对 build SHA、D1 revision、R2 对象、代表页面和 sitemap。失败停在 CI，不发布临时产物。

## 4. 五语翻译审计门禁

当前默认发布语种为 EN、ES、PT、RU、TR；运行时以 D1 `site_state.language_config` 中 enabled 且 publishReady 的语言为准。每个已配置语言资源发布前必须检查：

- html lang、title、H1、meta description、OG、正文、导航、分类、按钮、ALT、FAQ、JSON-LD 的可见文案与目标语言一致。
- 不得出现整句英文回退、旧语言目录、英文面包屑、英文分类侧栏或“只翻标题不翻正文”。OEM、ODM、B2B、MOQ、SKU、ml、oz、FAQ 等行业缩写和型号可以保留。
- 每个语言 URL 的 canonical、hreflang、sitemap 和内部链接必须指向同语言已发布页面；缺翻译时不生成假翻译链接。
- 发生一条高置信度漏翻译，就阻止该资源批次发布，进入 D1/CMS 翻译队列；禁止在构建后替换 HTML 规避门禁。

2026-11-05 线上只读审计结果：sitemap 1,812 个 URL，HTTP 错误 0，五语 html lang 错误 0。发现并已在共享模板修复 24 个多语分类侧栏英文回退、4 个 About 面包屑 Home；另有 9 个博客多语正文/相关阅读含英文片段，属于 D1/CMS 内容，必须按本标准回写 D1 后再复核，不能直接改成品文件。FAQ、OEM/ODM 和 Email 等上下文词未自动判定为漏翻译。

## 5. 回滚和交接

- 文本回滚使用 D1 旧版本/快照或 CMS 审计记录；媒体回滚使用旧 R2 对象和 D1 引用恢复；源码回滚使用 Git 提交，禁止用旧 dist 覆盖现状。
- 每次发布交接必须写明：D1 表/资源/语言、R2 对象和 SHA、Git 提交、构建/部署 run、测试结果、线上核验 URL、是否存在待处理翻译。
- 未完成 D1/R2 写入、翻译审核、双构建或线上核验时，状态只能写“草稿/待审核/未发布”，不能写“已完成”。

本文件是产品、博客、评价、翻译、图片、SEO/GEO 和 AI/工具发布的统一操作标准；与历史脚本或旧说明冲突时，以本文件、AGENTS.md 和 PROJECT_CHANGE_POLICY.md 为准。


## 2026-11-08 系统使用说明：人工 + AI API 双轨

本节是日常更新、发布和交接的统一入口。所有操作先读本节，再根据任务类型执行；人工和 AI API 只是两种操作方式，最终数据源、审核门禁和发布标准完全相同。

### 1. 人工模式（默认、首选）

1. 后台登录后先读取 D1/CMS 当前记录、语言配置、字段所有者和 publish revision。
2. 在正式后台编辑器修改产品、SEO、Blog、翻译、评价或联系人；图片先进入 R2，再在 D1 保存路径、ALT、语言和引用关系。
3. 保存草稿后人工核对事实、语言、容量 ml/oz、材质、B2B/OEM 词、链接、图片场景和结构化数据。
4. 只有完成审核并明确执行发布，才写入正式 D1/CMS；然后 bump publish revision，由标准构建从 D1 + R2 + GitHub 模板生成静态产物。
5. 发布后核对 CI、build SHA、D1 revision、代表性 URL、五语页面、canonical、hreflang、sitemap 和分页。

### 2. AI API 模式（辅助，不越权）

1. AI API 只能生成草稿、翻译初稿、SEO 组合建议、去重、格式整理、风险筛查或审计报告；不得凭空生成容量、材质、认证、MOQ、工厂证据、客户体验、评价或图片事实。
2. API 密钥只放受控 Secret，不写入 D1、GitHub 文件、日志、前台页面或提示词；任何费用、额度、试用赠金或计费条款不明确的 API 一律禁止。
3. AI API 输出先写入 D1/CMS 的任务或待审核状态，保存 source hash、资源 ID、语言、provider、操作者、时间和错误信息；不能直接把 API 输出当作已发布内容。
4. 人工审核通过后，按与人工模式相同的条件写入、publish revision、构建、回归和线上核验流程发布。除非项目规则和负责人明确允许，AI API 不得自动发布。
5. API 失败、字段缺失、源 hash 变化、语言未配置、D1 条件不满足或事实无法核验时，必须停止并报告，不能强制覆盖或自动重试覆盖。

### 3. 常见操作标准

| 操作 | 正式入口 | 必查内容 | 完成条件 |
| --- | --- | --- | --- |
| 产品 SEO / 内容 | D1/CMS 产品 SEO 与内容编辑器 | 型号、真实材质、容量 ml + 经审核 oz size class、颜色、定制、厂家/B2B 词、title/H1/description 差异化 | 条件写入 D1，五语与产品详情/列表/结构化数据回归通过 |
| Blog 新增/修改 | D1 Blog 编辑器 | B2B 场景、正文深度、2–5 个真实产品内链、2–3 篇相关阅读、封面场景、FAQ、SEO | 文章和翻译任务进入正确状态，审核通过后发布并核对列表顺序 |
| 产品评价 | D1 评价发布入口 | 可核验来源、精确 SKU、fingerprint、原文、星级、去重、北京时间每日上限 | 只写真实未发布评价，D1 记录 source/审核状态，不能改写事实 |
| 多语言翻译 | D1 translation_jobs / 正式页面编辑器 | 语种必须来自 D1 `language_config`，不以英文充当译文，不丢 HTML/链接/型号 | 每个语言独立审核；缺翻译、结构错误或英文片段达到门禁阈值时停止 |
| 图片 / 封面 / ALT | R2 + D1 媒体管理 | 来源、尺寸、格式、SHA-256、场景、版权、ALT 和引用关系 | 先成功写 R2，再写 D1；未通过引用检查不得删除旧对象 |
| 定时发布 | D1 scheduler / Blog 定时队列 | 状态、审批标记、时间、每日额度、源 hash、多语 payload | 只处理到期且条件完整的任务；完成记录保留在 D1，活动队列不重复显示 |
| 发布 / 回滚 | GitHub Actions + Cloudflare Pages | D1 revision、构建 SHA、CI、线上 URL、sitemap、代表语言 | CI 与线上核验完成后才报告已发布；回滚用 D1/R2/Git 正式历史，不覆盖业务数据 |

### 4. 语种、翻译与 Google Translate 网页边界

- 运行时语种唯一来源是 D1 的 `site_state.language_config`；当前默认是 EN/ES/PT/RU/TR，但新增、停用、可发布状态和顺序都以后台配置为准，代码不得另维护固定语种数组。
- 人工翻译直接在后台正式页面编辑器中完成；AI API 翻译只能生成任务草稿，审核通过后写入对应 `xuyi_translation_overrides`。
- Google Translate 网页是交互式免费工具，不是本系统的后端翻译 API；不得把网页抓取、非官方接口或浏览器自动搬运当作稳定发布链路。它的结果必须经过正式 D1/CMS 审核入口，不能绕过任务状态。
- 当前项目 API 禁用规则优先于任何旧 Provider 说明；未获明确授权前，不调用 Google Cloud Translation、DeepL、OpenAI 或其他费用/额度不明 API。

### 5. 固定验收与回滚标准

- 未完成 D1/R2 写入、翻译审核、双构建、CI 或线上核验时，状态只能写“草稿/待审核/未发布”。
- 文本回滚使用 D1 旧版本、快照或 CMS 审计记录；媒体回滚使用旧 R2 对象和 D1 引用恢复；源码回滚使用 Git 提交，禁止用旧 dist 覆盖现状。
- 每次交接必须写明：D1 表/资源/语言、R2 对象和 SHA、Git 提交、构建/部署 run、测试结果、线上核验 URL、待处理翻译和是否实际发布。
