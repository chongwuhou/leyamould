# XUYI 统一内容、翻译与媒体发布标准

生效日期：2026-11-05  
级别：P0，适用于人工、AI、localGPT、脚本、GitHub Actions、CMS 管理后台和后续所有自动化。

## 1. 先确定唯一真源

| 内容 | 唯一写入位置 | 禁止作为发布源 |
|---|---|---|
| 产品标题、H1、描述、OG、正文、翻译、博客、评价 | Cloudflare D1 / XUYI CMS 正式记录 | dist、线上 HTML、临时 JSON、一次性 HTML 替换 |
| 图片、封面、ALT 对应媒体 | Cloudflare R2；ALT 和引用关系写入 D1 | 直接替换网页图片地址、把本地文件当线上媒体 |
| 模板、组件、渲染器、回归测试、发布规则 | GitHub 源码 | 直接改生成页面 |
| dist、sitemap、静态页面 | 标准构建产物 | 手工修改后再发布 |

业务数据必须进入 D1；媒体必须先进入 R2，再由 D1 记录引用、ALT、语言和发布版本。源码模板可以在 GitHub 修改，但不能用源码里的临时内容绕过 D1 已有人工值。

## 2. AI 和工具的硬规则

- AI 只能做草稿、翻译初稿、SEO 组合建议、去重、格式整理、风险筛查和审计；不能凭空补造容量、材质、认证、MOQ、工厂证据、客户体验、评价或图片事实。
- AI 生成的产品、博客、翻译和评价，必须先进入“待审核”状态；审核通过后才能条件写入 D1。评价必须有可核验来源、准确 SKU、fingerprint、source 和审核状态。
- 工具默认只读或 dry-run。实际写入必须使用现有、已鉴权的 XUYI D1/CMS 或 R2 管理入口，并明确记录操作者、批次、时间、旧值摘要、新值摘要和 publish revision。
- 禁止脚本、插件、自动化或 AI 直接写 dist、线上 HTML、Cloudflare Pages 成品或 R2 缓存来冒充发布。禁止用旧静态回退表覆盖后台编辑。
- 工具必须幂等：重复运行不重复插入、不删除已有数据、不回退人工修改；更新必须按资源 ID、语言、SKU 和旧值/指纹条件写入。条件不满足就停止并报告，不强制覆盖。
- 任何计费、额度、试用赠金或费用不明确的 API 禁止使用；只用项目已批准且可确认安全的连接。

## 3. 产品、博客、评价和图片发布顺序

1. 读取 D1/CMS 当前记录、字段所有者和 publish revision，先做可恢复快照。
2. 读取真实产品/文章/评价来源，生成待审核草稿；翻译必须逐语言检查，不用英文正文自动充当译文。
3. 人工确认事实、SEO、五语、链接和图片场景。博客正文放 2–5 个真实相关产品链接，结尾人工选择 2–3 篇相关阅读。
4. 新图片先校验来源、尺寸、格式、SHA-256 和场景，再上传 R2 新对象；R2 成功后才写 D1 图片路径、ALT、语言和引用。原对象不覆盖、不删除，除非通过引用检查和可恢复流程。
5. 对 D1 做条件写入并 bump publish revision；失败或版本冲突时停止，不自动重试覆盖。
6. 由标准构建从 D1 + R2 + GitHub 模板生成 dist；必须完成两次干净构建、回归测试和 CMS owner-edit 保留测试。
7. 通过 CI 后才部署；部署后核对 build SHA、D1 revision、R2 对象、代表页面和 sitemap。失败停在 CI，不发布临时产物。

## 4. 五语翻译审计门禁

五个正式语言为 EN、ES、PT、RU、TR。每个资源发布前必须检查：

- html lang、title、H1、meta description、OG、正文、导航、分类、按钮、ALT、FAQ、JSON-LD 的可见文案与目标语言一致。
- 不得出现整句英文回退、旧语言目录、英文面包屑、英文分类侧栏或“只翻标题不翻正文”。OEM、ODM、B2B、MOQ、SKU、ml、oz、FAQ 等行业缩写和型号可以保留。
- 每个语言 URL 的 canonical、hreflang、sitemap 和内部链接必须指向同语言已发布页面；缺翻译时不生成假翻译链接。
- 发生一条高置信度漏翻译，就阻止该资源批次发布，进入 D1/CMS 翻译队列；禁止在构建后替换 HTML 规避门禁。

2026-11-05 线上只读审计结果：sitemap 1,812 个 URL，HTTP 错误 0，五语 html lang 错误 0。发现并已在共享模板修复 24 个多语分类侧栏英文回退、4 个 About 面包屑 Home；另有 9 个博客多语正文/相关阅读含英文片段，属于 D1/CMS 内容，必须按本标准回写 D1 后再复核，不能直接改成品文件。FAQ、OEM/ODM 和 Email 等上下文词未自动判定为漏翻译。

## 5. 回滚和交接

- 文本回滚使用 D1 旧版本/快照或 CMS 审计记录；媒体回滚使用旧 R2 对象和 D1 引用恢复；源码回滚使用 Git 提交，禁止用旧 dist 覆盖现状。
- 每次发布交接必须写明：D1 表/资源/语言、R2 对象和 SHA、Git 提交、构建/部署 run、测试结果、线上核验 URL、是否存在待处理翻译。
- 未完成 D1/R2 写入、翻译审核、双构建或线上核验时，状态只能写“草稿/待审核/未发布”，不能写“已完成”。

本文件是产品、博客、评价、翻译、图片、SEO/GEO 和 AI/工具发布的统一操作标准；与历史脚本或旧说明冲突时，以本文件、AGENTS.md 和 PROJECT_CHANGE_POLICY.md 为准。


## 2026-11-08 多语言 Blog 编辑与翻译开关

- 已发布 Blog 路径纳入现有“多语言正式页面”编辑器；编辑入口仍写入 `xuyi_translation_overrides`，资源 ID 使用 `page:/blog/<slug>/`，不另建旁路内容表。
- 翻译策略固定为三态：`off`（不自动机翻，人工处理）、`review`（自动机翻后必须人工审核）、`publish`（自动机翻后自动写入已审核译文）。默认仍为 `off`，并保留源内容变更后的任务队列和幂等条件写入。
- Google Cloud Translation 仅作为后台可选的官方 Provider；密钥只允许放 Cloudflare Pages Secret，D1 只保存任务状态和译文结果，不保存密钥。启用前由负责人确认 Google 账号的配额/计费设置；未启用时不得发起外部翻译请求。
- Blog 自动翻译任务的源内容由已发布 D1 Blog 文章和共享模板生成，审核通过后才写入正式多语言页面；HTML 经过长度和危险标签检查。产品翻译旧结构保持兼容。
- 多语言列表排序不是翻译文本的副作用：每次定时 Blog 发布完成后，必须重新读取 `listBlogPosts(db,'published')` 的完整 D1 顺序，重排 ES/PT/RU/TR 卡片并验证五语 slug 集合、数量和顺序；缺卡、重复、额外卡或并发条件不满足时停止。
- 2026-11-08 线上复核基线：EN/ES/PT/RU/TR 均为 76 篇，五份列表的完整 slug 顺序一致，11 月 7 日新增三篇位于共同的 D1 顺序位置；当前实现已把顺序保护从一次性修复提到通用定时发布器。
