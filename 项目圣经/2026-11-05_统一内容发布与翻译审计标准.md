# XUYI 统一内容、翻译与媒体发布标准

生效日期：2026-11-05  
级别：P0，适用于人工、AI、localGPT、脚本、GitHub Actions、CMS 管理后台和后续所有自动化。

## 1. 先确定唯一真源

| 内容 | 唯一写入位置 | 禁止作为发布源 |
|---|---|---|
| 产品标题、H1、描述、OG、正文、翻译、博客、评价 | Cloudflare D1 / XUYI CMS 正式记录 | dist、线上 HTML、临时 JSON、一次性 HTML 替换 |
| 图片、封面、ALT 对应媒体 | Cloudflare R2；ALT 和引用关系写入 D1 | 直接替换网页图片地址、把本地文件当线上媒体 |
| 模板、组件、渲染器、回归测试、发布规则 | GitHub 源码 | 直接改生成页面 |
| dist、sitemap、静态页面 | 标准构建产物 | 手工修改后再发布 |

业务数据必须进入 D1；媒体必须先进入 R2，再由 D1 记录引用、ALT、语言和发布版本。源码模板可以在 GitHub 修改，但不能用源码里的临时内容绕过 D1 已有人工值。

## 2. AI 和工具的硬规则

- AI 只能做草稿、翻译初稿、SEO 组合建议、去重、格式整理、风险筛查和审计；不能凭空补造容量、材质、认证、MOQ、工厂证据、客户体验、评价或图片事实。
- AI 生成的产品、博客、翻译和评价，必须先进入“待审核”状态；审核通过后才能条件写入 D1。评价必须有可核验来源、准确 SKU、fingerprint、source 和审核状态。
- 工具默认只读或 dry-run。实际写入必须使用现有、已鉴权的 XUYI D1/CMS 或 R2 管理入口，并明确记录操作者、批次、时间、旧值摘要、新值摘要和 publish revision。
- 禁止脚本、插件、自动化或 AI 直接写 dist、线上 HTML、Cloudflare Pages 成品或 R2 缓存来冒充发布。禁止用旧静态回退表覆盖后台编辑。
- 工具必须幂等：重复运行不重复插入、不删除已有数据、不回退人工修改；更新必须按资源 ID、语言、SKU 和旧值/指纹条件写入。条件不满足就停止并报告，不强制覆盖。
- 任何计费、额度、试用赠金或费用不明确的 API 禁止使用；只用项目已批准且可确认安全的连接。

## 3. 产品、博客、评价和图片发布顺序

1. 读取 D1/CMS 当前记录、字段所有者和 publish revision，先做可恢复快照。
2. 读取真实产品/文章/评价来源，生成待审核草稿；翻译必须逐语言检查，不用英文正文自动充当译文。
3. 人工确认事实、SEO、全部已配置发布语种、链接和图片场景。博客正文放 2–5 个真实相关产品链接，结尾人工选择 2–3 篇相关阅读。
4. 新图片先校验来源、尺寸、格式、SHA-256 和场景，再上传 R2 新对象；R2 成功后才写 D1 图片路径、ALT、语言和引用。原对象不覆盖、不删除，除非通过引用检查和可恢复流程。
5. 对 D1 做条件写入并 bump publish revision；失败或版本冲突时停止，不自动重试覆盖。
6. 由标准构建从 D1 + R2 + GitHub 模板生成 dist；必须完成两次干净构建、回归测试和 CMS owner-edit 保留测试。
7. 通过 CI 后才部署；部署后核对 build SHA、D1 revision、R2 对象、代表页面和 sitemap。失败停在 CI，不发布临时产物。

## 4. 全部已配置发布语种翻译审计门禁

发布语种不在代码或流程文档中固定列举；运行时以 D1 `site_state.language_config` 中 enabled 且 publishReady 的语言为准。每个已配置语言资源发布前必须检查：

- html lang、title、H1、meta description、OG、正文、导航、分类、按钮、ALT、FAQ、JSON-LD 的可见文案与目标语言一致。
- 不得出现整句英文回退、旧语言目录、英文面包屑、英文分类侧栏或“只翻标题不翻正文”。OEM、ODM、B2B、MOQ、SKU、ml、oz、FAQ 等行业缩写和型号可以保留。
- 每个语言 URL 的 canonical、hreflang、sitemap 和内部链接必须指向同语言已发布页面；缺翻译时不生成假翻译链接。
- 发生一条高置信度漏翻译，就阻止该资源批次发布，进入 D1/CMS 翻译队列；禁止在构建后替换 HTML 规避门禁。

2026-11-05 线上只读审计结果：sitemap 1,812 个 URL，HTTP 错误 0，全部已配置发布语种 html lang 错误 0。发现并已在共享模板修复 24 个多语分类侧栏英文回退、4 个 About 面包屑 Home；另有 9 个博客多语正文/相关阅读含英文片段，属于 D1/CMS 内容，必须按本标准回写 D1 后再复核，不能直接改成品文件。FAQ、OEM/ODM 和 Email 等上下文词未自动判定为漏翻译。

## 5. 回滚和交接

- 文本回滚使用 D1 旧版本/快照或 CMS 审计记录；媒体回滚使用旧 R2 对象和 D1 引用恢复；源码回滚使用 Git 提交，禁止用旧 dist 覆盖现状。
- 每次发布交接必须写明：D1 表/资源/语言、R2 对象和 SHA、Git 提交、构建/部署 run、测试结果、线上核验 URL、是否存在待处理翻译。
- 未完成 D1/R2 写入、翻译审核、双构建或线上核验时，状态只能写“草稿/待审核/未发布”，不能写“已完成”。

本文件是产品、博客、评价、翻译、图片、SEO/GEO 和 AI/工具发布的统一操作标准；与历史脚本或旧说明冲突时，以本文件、AGENTS.md 和 PROJECT_CHANGE_POLICY.md 为准。


## 2026-11-08 系统使用说明：人工 + AI API 双轨

本节是日常更新、发布和交接的统一入口。所有操作先读本节，再根据任务类型执行；人工和 AI API 只是两种操作方式，最终数据源、审核门禁和发布标准完全相同。

### 1. 人工模式（默认、首选）

1. 后台登录后先读取 D1/CMS 当前记录、语言配置、字段所有者和 publish revision。
2. 在正式后台编辑器修改产品、SEO、Blog、翻译、评价或联系人；图片先进入 R2，再在 D1 保存路径、ALT、语言和引用关系。
3. 保存草稿后人工核对事实、语言、容量 ml/oz、材质、B2B/OEM 词、链接、图片场景和结构化数据。
4. 只有完成审核并明确执行发布，才写入正式 D1/CMS；然后 bump publish revision，由标准构建从 D1 + R2 + GitHub 模板生成静态产物。
5. 发布后核对 CI、build SHA、D1 revision、代表性 URL、全部已配置发布语种页面、canonical、hreflang、sitemap 和分页。

### 2. AI API 模式（辅助，不越权）

1. AI API 只能生成草稿、翻译初稿、SEO 组合建议、去重、格式整理、风险筛查或审计报告；不得凭空生成容量、材质、认证、MOQ、工厂证据、客户体验、评价或图片事实。
2. API 密钥只放受控 Secret，不写入 D1、GitHub 文件、日志、前台页面或提示词；任何费用、额度、试用赠金或计费条款不明确的 API 一律禁止。
3. AI API 输出先写入 D1/CMS 的任务或待审核状态，保存 source hash、资源 ID、语言、provider、操作者、时间和错误信息；不能直接把 API 输出当作已发布内容。
4. 人工审核通过后，按与人工模式相同的条件写入、publish revision、构建、回归和线上核验流程发布。除非项目规则和负责人明确允许，AI API 不得自动发布。
5. API 失败、字段缺失、源 hash 变化、语言未配置、D1 条件不满足或事实无法核验时，必须停止并报告，不能强制覆盖或自动重试覆盖。

### 3. 常见操作标准

| 操作 | 正式入口 | 必查内容 | 完成条件 |
| --- | --- | --- | --- |
| 产品 SEO / 内容 | D1/CMS 产品 SEO 与内容编辑器 | 型号、真实材质、容量 ml + 经审核 oz size class、颜色、定制、厂家/B2B 词、title/H1/description 差异化 | 条件写入 D1，全部已配置发布语种与产品详情/列表/结构化数据回归通过 |
| Blog 新增/修改 | D1 Blog 编辑器 | B2B 场景、正文深度、2–5 个真实产品内链、2–3 篇相关阅读、封面场景、FAQ、SEO | 文章和翻译任务进入正确状态，审核通过后发布并核对列表顺序 |
| 产品评价 | D1 评价发布入口 | 可核验来源、精确 SKU、fingerprint、原文、星级、去重、北京时间每日上限 | 只写真实未发布评价，D1 记录 source/审核状态，不能改写事实 |
| 多语言翻译 | D1 translation_jobs / 正式页面编辑器 | 语种必须来自 D1 `language_config`，不以英文充当译文，不丢 HTML/链接/型号 | 每个语言独立审核；缺翻译、结构错误或英文片段达到门禁阈值时停止 |
| 图片 / 封面 / ALT | R2 + D1 媒体管理 | 来源、尺寸、格式、SHA-256、场景、版权、ALT 和引用关系 | 先成功写 R2，再写 D1；未通过引用检查不得删除旧对象 |
| 定时发布 | D1 scheduler / Blog 定时队列 | 状态、审批标记、时间、每日额度、源 hash、多语 payload | 只处理到期且条件完整的任务；完成记录保留在 D1，活动队列不重复显示 |
| 发布 / 回滚 | GitHub Actions + Cloudflare Pages | D1 revision、构建 SHA、CI、线上 URL、sitemap、代表语言 | CI 与线上核验完成后才报告已发布；回滚用 D1/R2/Git 正式历史，不覆盖业务数据 |

### 4. 语种、翻译与 Google Translate 网页边界

- 运行时语种唯一来源是 D1 的 `site_state.language_config`；发布语种不在代码或流程文档中固定列举；新增、停用、可发布状态和顺序都以后台配置为准，代码不得另维护固定语种数组。
- 人工翻译直接在后台正式页面编辑器中完成；AI API 翻译只能生成任务草稿，审核通过后写入对应 `xuyi_translation_overrides`。
- Google Translate 网页是交互式免费工具，不是本系统的后端翻译 API；不得把网页抓取、非官方接口或浏览器自动搬运当作稳定发布链路。它的结果必须经过正式 D1/CMS 审核入口，不能绕过任务状态。
- 当前项目 API 禁用规则优先于任何旧 Provider 说明；未获明确授权前，不调用 Google Cloud Translation、DeepL、OpenAI 或其他费用/额度不明 API。

### 5. 固定验收与回滚标准

- 未完成 D1/R2 写入、翻译审核、双构建、CI 或线上核验时，状态只能写“草稿/待审核/未发布”。
- 文本回滚使用 D1 旧版本、快照或 CMS 审计记录；媒体回滚使用旧 R2 对象和 D1 引用恢复；源码回滚使用 Git 提交，禁止用旧 dist 覆盖现状。
- 每次交接必须写明：D1 表/资源/语言、R2 对象和 SHA、Git 提交、构建/部署 run、测试结果、线上核验 URL、待处理翻译和是否实际发布。

## 5.1 后台 06 / 08 功能边界

后台只保留一个明确归属，避免同一条数据出现两个编辑入口：

| 模块 | 负责内容 | 不负责内容 |
|---|---|---|
| 06 内容基础 · 来源与页面 | 来源语言品牌、Banner、导航、普通页面 SEO/正文、产品来源资料、新建产品、普通页面与 Blog 多语言正式页面 | 产品多语言 SEO、产品目标语种正文 |
| 08 产品多语言 SEO + 正文 | 产品型号选择、各已配置语种 SEO Title、Meta Description、目标语种完整 Main HTML | 品牌、导航、普通页面、Blog、来源语言产品商详字段 |

产品来源字段只在 06 的“产品来源内容”维护；产品 SEO 和目标语种正文只在 08 维护。现有 D1 表和 API 不迁移、不复制、不重新发布数据，只调整后台入口和筛选范围。

## 5.2 2026-11-08 系统可用性审计加固

本次全量代码审核已落实以下固定规则：

- 后台 06/08 的产品归属以 D1 为准；06 不再展示产品多语言翻译入口，产品 Title、Meta Description 和目标语种正文统一由 08 管理。
- 后台 HTML、管理员 JS/CSS 使用 no-store / must-revalidate，避免旧缓存继续显示已废弃入口。
- Blog 定时发布的目标语种数量、状态核验和完成判断全部读取 D1 language_config，禁止写死语种数量。
- 页面多语言路由：普通页面必须存在于 D1 页面配置或兼容路由索引；Blog 和产品翻译资格必须分别核验 D1 已发布记录。
- 外部翻译 API 永久关闭。人工或当前 AI 会话只能生成待审核草稿；审核通过后才写入 D1，不保存、不探测、不调用 Google Cloud Translation、DeepL、OpenAI 或其他费用/额度不明接口。
- 仍保留的静态路由/型号清单只能作为历史兼容索引，不能决定当前产品数量、产品发布资格、语种数量或翻译资格。要彻底移除这部分历史兼容清单，必须先完成 D1 产品注册表的无损盘点和迁移，再删除旧入口。
- 当前 Blog 动态 Function 仍是 D1 发布内容的兼容覆盖层；静态构建仍是默认产物。若后续 CPU 告警，先拆分为“静态默认 + 明确按需动态”的链路，不直接删除 D1 回退。
### 6. 直接发布 Blog 的永久默认口径（2026-11-08）

接收到“发布、上线或更新 Blog”且用户没有另行限定时，默认执行完整多语发布，不以只发布英文作为完成：

- 发布范围以 D1 `site_state.language_config` 为唯一准绳：英文源文 + 所有 `enabled=true` 且 `publishReady=true` 的目标语种；不得在代码或操作说明中另维护固定语种清单。每个目标语种必须独立写入标题、H1、description、正文、FAQ、CTA、ALT 和 Blog 列表卡片，禁止英文回退。
- 后台 08「产品 SEO · 多语言 D1」是产品多语言维护的统一入口：按产品型号和 D1 语种配置同时维护 SEO Title、Meta Description 与目标语种完整 Main HTML；来源语言正文仍由 06 产品商详维护。正文必须通过现有 `xuyi_translation_overrides` 写入，正文留空只保存 SEO，不得清空已有正文；来源语言正文不得在 08 入口另建覆盖记录。
- 后台 08 的产品数量、型号、语种、语言名称和可发布资格全部来自 D1/配置接口；构建快照、产品 hreflang、SEO 记录筛选和多语渲染均不得使用固定语种数组或固定语言数量。
- 针对 AI、localGPT、脚本和自动化工具，文章更新全过程只走受控 API，不打开浏览器后台、不通过浏览器搬运翻译、不手工改线上 HTML。人工操作者可以在正式后台浏览器中编辑、审核和发布。标准链路为：D1/CMS 读取与条件写入 → 图片经审核后上传 R2 → D1 保存媒体引用 → 多语覆盖写入 → bump publish revision → GitHub Actions 标准构建/CI → Cloudflare Pages 部署 → API/线上 URL 回读。任何一步失败即停止，不绕过 D1、R2 或构建流程。
- 新 B2B 文章必须有独立搜索意图和标题/H1，围绕采购决策直接回答问题，正文有真实产品内链、相关阅读、FAQ/清单和可核验边界；多语版本不能只翻标题。SEO/GEO 采用 people-first、独特信息、清晰问题式结构、可核验事实和自然内链；不使用所谓“GEO 特殊作弊标签”或无依据承诺，沿用站内既有 BlogPosting、canonical、hreflang 和 sitemap 模板。
- 封面图片必须先人工目视核对文章行业与采购场景，再压缩为清晰的 WebP 上传 R2；每篇使用独立图片并记录尺寸、SHA-256、来源/生成说明、ALT 和“编辑插图而非真实订单/工厂/型号证据”的边界。不得用一张通用图批量复用，也不得把 AI 图当作客户或工厂证明。
- 翻译默认由人工或当前 AI 会话生成草稿后，经 D1/CMS 正式审核写入；不调用 Google Cloud Translation、DeepL、OpenAI 或任何费用/额度不明确的外部翻译 API。Google Translate 网页不属于发布链路，也不允许浏览器自动化代替 D1 写入。
- 完成验收必须包含：D1/R2 写入结果、publish revision、构建/部署结果、英文及全部目标语种文章 URL 状态 200、html lang/title/H1/canonical/hreflang、封面可读、正文结构/FAQ/内链、Blog 列表卡片数量与 D1 顺序一致，以及无整句英文回退。未通过上述核验只能标记为草稿或待审核。


## 7. 2026-11-08 发布复盘：固定流程与源头清理（P0）

本节把最近一次 Blog 发布中实际踩到的坑写成永久执行卡。以后 localGPT、人工、AI API、脚本和 GitHub Actions 都直接按这里执行，不再重新研究或临时发明流程。

### 7.1 先清理源头，再写标准

已清理并固化以下源代码问题：

- 语种列表、启用状态、publishReady、URL 前缀和排序只认 D1 `site_state.language_config`。调度器、批量入口和语言队列不允许再写死语种数组或 SQLite 语种 CHECK；旧队列表迁移时必须先完整复制并核对行数，确认无损后才替换。
- 多语 Blog 列表只认英文运行时 `listBlogPosts(db,"published")` 的完整 D1 顺序；其他语种用同一顺序重排自己已有的翻译卡片，不得把“本次新增的文章”直接推到列表头部，也不得只修前三篇。
- 多语路径匹配必须读取 D1 的 `pathPrefix`，不得使用只支持两位字母的正则；新 BCP47 语种必须能在不改代码数组的情况下进入审核流程。
- 定时发布队列只显示未完成的 `scheduled/needs_review`；`published/cancelled` 历史记录保留在 D1，供审计和回滚，不再污染后台活动列表。
- 统一文章源 HTML 的兼容字段：`blog-meta` 时间线、XUYI 品牌眉标、正文章节、FAQ、产品内链和相关阅读必须由 D1/CMS 数据与共享渲染器生成；不得在 dist 上补标签。
- `approve_job` 只代表 D1 审核状态，不代表线上发布。审批后必须重新 bump revision、两次干净构建、CI、部署和线上回读。

### 7.2 Blog 发布固定执行卡

1. 先读本文件、`PROJECT_CHANGE_POLICY.md`、`AGENTS.md`，读取 D1 当前 revision、language_config、文章当前值和字段所有者。
2. 只通过受控 API 读取/写入 D1/CMS；文章、翻译、评价、SEO 和任务写 D1，图片先写 R2 再在 D1 写引用、ALT、语言和 SHA-256。
3. 默认发布范围是英文源文加 D1 中所有 `enabled=true && publishReady=true` 的目标语种；不得自己填写 EN/ES/PT/RU/TR 等固定列表。若只有英文处于 publish-ready，就只发布英文并明确记录原因。
4. 新文章必须独立标题/H1/搜索意图，正文直接解决 B2B 采购问题；自然放置 2–5 个真实产品内链、2–3 篇相关阅读、FAQ/清单和事实边界。不能补造材质、容量、认证、MOQ、工厂、客户或评价事实。
5. 图片必须先人工目视核对文章主题、行业和采购场景；每篇独立使用清晰压缩 WebP，记录 R2 路径、尺寸、SHA-256、ALT、来源/生成说明及“编辑插图而非真实订单/工厂证据”的边界。
6. 翻译先形成逐语种草稿，再进入正式 D1/CMS 审核；检查 title、H1、description、正文、FAQ、CTA、ALT、列表卡片、canonical、hreflang、链接和 html lang。整句英文回退、语言目录错误、HTML 结构缺失或 source hash 改变时停止。
7. AI、localGPT、脚本和自动化的文章更新全过程不调用浏览器：D1/CMS 读取与条件写入 → R2 上传 → 多语 override/translation job → bump revision → GitHub Actions 干净构建/CI → Cloudflare Pages 部署 → API 和线上 URL 回读。人工操作者可以使用正式后台浏览器完成编辑和审核，但不得改 dist、线上 HTML、Pages 成品或 R2 缓存；AI 不得通过浏览器搬运 Google Translate。
8. Blog 列表验收必须逐项比较英文与每个已发布语种：总数、slug 集合、卡片顺序、详情链接、图片和语言内容；排序以 D1 完整结果为准，不能只看首页前三条。
9. 最终必须记录：D1 表/资源/语言、R2 对象与 SHA、publish revision、Git 提交、构建/部署 run、CI 结果、15/全部实际 URL（按当前语种数量）、列表数量/顺序和待处理翻译。任何一步未通过，只能标记草稿/待审核/未发布。

### 7.3 API 和费用边界

- Google Translate 网页不是后端发布 API；人工可以把它作为辅助参考，但不得把网页结果直接当作已审核译文。AI、localGPT、脚本和自动化禁止浏览器自动化搬运。Google Cloud Translation、DeepL、OpenAI 或其他费用/额度/试用赠金不明确的 API，在项目费用禁令解除前一律不调用。
- AI 只负责草稿、翻译初稿、SEO 组合、去重、格式整理和审计；事实核验和正式发布仍由 D1/CMS 审核门禁决定。
- 工具默认只读/dry-run；正式写入必须使用已鉴权的正式 API，条件不满足、版本冲突、字段缺失或语言未注册时停止，不强制覆盖。

### 7.4 固定验收命令/检查项

每次发布至少验证：

- D1 文章状态、翻译状态、媒体引用和 publish revision；
- R2 图片 HEAD、Content-Type、大小、尺寸和 SHA-256；
- 两次 clean build、所有相关 CI、部署 build SHA；
- 英文及所有 D1 publish-ready 语种文章 URL 状态 200；
- html lang、title、H1、description、canonical、hreflang、FAQ/BlogPosting、sitemap；
- Blog 列表数量、slug 集合和完整顺序；
- 活动定时队列无已完成项目；
- 重复执行无新增重复卡片、无字段回退、无旧英文覆盖人工翻译。

本节是后续文章发布的默认标准；与历史脚本、旧批处理入口、聊天上下文或生成产物冲突时，以 D1、共享模板、CI 门禁、本文件和 `PROJECT_CHANGE_POLICY.md` 为准。
