# LEYA MOULD 后台模块化与更新流程

## 目标

前台 `templates/site`、`assets/site.css`、`assets/site.js` 和 `mould_build.py` 的版式是冻结的视觉源。后台只负责审核后的业务数据，不直接改写前台 CSS，也不把后台 HTML 当成新的模板。

## 数据真源

- Cloudflare D1：品牌与联系方式、语言配置、导航、页面 SEO、页面正文、模具分类内容、新闻/Blog、YouTube 视频、发布版本号。
- Cloudflare R2：经审核的图片、PDF、视频相关媒体和 ALT 文案。
- GitHub：模板、渲染器、Functions、管理端和测试；不存放生产数据库内容。
- `data/mould-catalog.json`：D1 无快照或字段为空时的安全回退，只包含 LEYA MOULD 模具分类。

## 发布链路

1. 管理后台写入 D1/R2，所有写入经过管理员认证、字段校验和发布版本号递增。
2. GitHub Actions 在构建前调用只读 `/api/build-snapshot`，将当前已发布内容保存为 `_local_ops/build-snapshot.json`。
3. `mould_build.py` 读取快照，覆盖品牌、导航标签、SEO、页面正文、分类内容、Banner、新闻和 YouTube 视频；未发布或不合法的数据自动回退到源模板。
4. 运行语法、隔离、路由、模板和双构建测试；通过后才部署 Pages。
5. 第二次重新读取快照并清洁构建，确认构建结果不依赖旧的 `dist` 或旧快照。

## 后台模块边界

品牌/联系方式、语言、导航、页面 SEO、页面正文、模具分类、Blog/News、YouTube 视频、Banner、媒体 ALT、询盘、评价和发布状态均为独立模块。模块之间通过 D1 的明确字段连接，不能借用水杯项目的商品、分类或业务数据。

## 安全与回滚

- `functions/_shared/mould-routes.js` 是模具路由和九个分类的写入白名单；旧的 `xuyi-routes.js` 只保留兼容导出，不再接受水杯型号。
- 构建快照只输出模具路由、九个模具分类和公开内容，不输出询盘、密钥或其他私有表。
- 发布失败时不修改线上站点；修正数据后重新递增发布版本并重跑双构建。需要回滚模板时回滚 GitHub 提交，需要回滚业务内容时恢复 D1/R2 的已审核记录。
