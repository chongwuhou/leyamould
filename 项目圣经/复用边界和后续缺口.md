# XUYI 复用边界与后续缺口

## 当前原则

1. 共享模板、D1/CMS 数据、R2 媒体和 GitHub Actions 发布链路由 XUYI 自己维护。
2. 业务数据、品牌信息、数据库、媒体、凭据和历史验收材料只允许来自 XUYI 自身来源。
3. 任何新功能必须先进入源模板、源模块或 D1/CMS，再由统一构建生成静态页面；不直接改 dist、线上 HTML 或单个生成页。
4. 只保留适合塑料水杯 B2B 业务的通用能力；行业专用字段、历史项目数据和无关迁移工具不进入当前系统。
5. 对所有会写入 D1/R2 的操作执行权限校验、幂等校验、回读验证和发布后线上核验。

## 已纳入系统

- Cloudflare Pages 静态预渲染、Pages Functions、D1 内容真源与 R2 媒体。
- 共享页面模板、统一导航、页面 SEO、产品 SEO、多语言翻译审核和博客发布队列。
- GitHub Actions 构建、文件数保护、链接/结构化数据/多语言/媒体引用回归检查。
- 产品、页面、Blog、翻译、媒体和发布修订的后台 API；草稿不会直接进入公开构建。

## 当前边界

- 产品和部分业务页面仍由受控 Python 源模块生成，D1 已接管的内容优先由快照构建，不能把本地源文件当成线上业务数据。
- 多语言页面只发布 D1 中已审核、已配置且有来源页面的内容；未审核内容不生成伪翻译。
- 静态构建默认从 D1/CMS 快照生成；Pages Functions 仅保留后台、询盘、媒体和必要的动态读取能力。
- `factory-catalog-20261103` 仍是当前 58 个型号的正式兼容 API、manifest 和回归夹具；日期是该目录审核来源的版本标识，不是一次性历史发布入口。在 D1 目录迁移完成并保留旧路由兼容前，不删除或擅自改名。
- 不引入第二个内容平台、常驻服务器、未经批准的翻译服务或费用/额度不明的 API。

## 后续缺口

- 产品与普通页面继续按真实字段逐步迁移到 D1，保持 URL、SEO 和现有数据不变。
- 继续完善多语言后台的编辑、审核、排序和回读验收。
- 对 R2 引用、媒体 ALT、删除保护和发布修订保持自动回归。
- 任何上线前改动都要以 CI 成功、生产 build-meta 修订号和线上路由检查为最终依据。

## 禁止误操作

不得修改无关项目、无关 Cloudflare 资源或无关数据库；不得把外部业务资料、品牌、产品、密钥或媒体写入 XUYI。
