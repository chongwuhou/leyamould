# LEYA MOULD 日常内容与评价发布标准

版本：2026-11-24
适用项目：LEYA MOULD 模具站
生产站点：`https://leyamould.com`

本手册把“日常发布”定义为可重复的内容批次，而不是固定每天生成几篇文章或几条评价。没有真实来源、审核授权和完整回读时，任务停在草稿，不以数量达标为目标。

## 1. 日常批次边界

- Blog/News、型号参考、产品资料、YouTube 视频、评价和案例分别走对应 D1/CMS 模块；不得用一个批次脚本互相冒充。
- 每批先读取 D1 当前已发布记录、`language_config`、字段更新时间、媒体引用和 publish revision；新增内容不受历史数量限制。
- 内容必须说明真实来源、目标买家、采购意图和待核实边界。AI 只能起草、翻译、整理和审计，不能编造事实。
- 评价和客户案例只在获得真实来源与授权后发布；没有证据时不发布“模拟评价”。

## 2. News/Blog 编辑门禁

每篇准备以下材料：

- 唯一 slug、目标买家和一个明确的采购/工程问题；
- 英文源稿以及当前 D1 `publishReady` 语言的完整译文；
- Title、H1、Meta、OG、首段、实质章节、FAQ（确有问题才加入）、CTA 和内部链接；
- 正文中 2–5 个真实相关的 LEYA 产品/型号详情链接，文末 2–3 篇人工选择的已发布相关阅读；
- 事实来源、数字/参数证据、图片来源与授权说明。

文章不能用通用话术、旧水杯内容、虚构客户、认证、订单、交期、MOQ 或工厂实拍填充。标题、H1、Meta 和正文由 D1/CMS 最终字段驱动；不直接编辑 `dist/` 或线上 HTML。

## 3. 图片和 PDF

1. 先完整阅读标题和正文，再实际查看最终图片，确认画面与模具/工程采购场景一致。
2. 记录来源、授权边界、可见主体、场景契合理由、尺寸、MIME、压缩结果和 SHA-256。
3. 优先使用压缩后的 WebP；Blog 封面默认 1200×800、3:2、30–350KB，产品图片以清晰度、无水印、无错位和合理体积为准。
4. PDF 记录页数、来源、语言、文件大小、SHA 和适用产品族；未经核验的参数不得写进页面。
5. 先上传 R2 并 HEAD 验证，再写 D1 的 URL、ALT、语言和引用关系。后台主动换图始终优先。

## 4. YouTube 视频

- 后台记录 YouTube URL、视频标题/多语标题、描述、分类、发布时间、缩略图、来源和公开状态。
- 发布时间只取后台字段；下架、无效、重复或未完成翻译的视频先保持草稿。
- 增删改必须通过视频模块的正式管理入口；列表、详情和语言页从同一 D1 snapshot 生成。

## 5. 发布前 dry-run

1. 获取最新 D1 snapshot 和 R2 使用索引。
2. 检查 slug、语言集合、重复主题、产品链接、相关阅读、图片/PDF manifest 和事实来源。
3. 检查每个 `publishReady` 语言是否有独立标题、正文、SEO、ALT、canonical、hreflang 和列表卡片。
4. 检查 R2 对象 HTTP/MIME/SHA，D1 写入是否为条件更新；冲突、超时或不明响应立即停止并只读核验。
5. 通过后台或正式 HTTPS API 写入 D1，读取写入数量和 publish revision；没有明确授权只能保存草稿。

## 6. 构建和线上验收

- 从最新 snapshot 连续执行两次干净构建；运行模板、路由、链接、SEO、结构化数据、多语和媒体测试。
- CI/Pages 完成后核对 `build-meta.json`、`r2-usage-index.json`、代表列表/详情页、sitemap、canonical/hreflang、OG 和媒体 HTTP 200。
- 对每个发布语言核对详情页和列表卡片的 slug 集合、顺序、标题、图片和内链；不可用“首页能打开”代替内容验收。
- 没有 D1/R2、CI、revision 和 URL 证据只能写“待构建/待验证”。

## 7. 评价与案例单独门禁

- 原文、作者/公司身份、国家、项目关系、授权、时间和来源必须可核验；保存 fingerprint 和审核记录。
- 不重复发布同一来源；后台删除不等于可以再次使用。
- 未核实的文案、星级、交付结果、图片和人物只能进入内部草稿，不可进入公开页面。

## 8. 失败处理与记录

| 失败点 | 处理 | 禁止 |
| --- | --- | --- |
| R2 超时/响应不明 | 按 SHA/HEAD 查询后再决定是否重试 | 盲目重复上传 |
| D1 超时/响应不明 | 读取记录、账本和 revision | 重复 POST |
| 翻译或列表缺失 | 修复 D1/CMS 字段和共享渲染器 | 直接改生成 HTML |
| 构建失败 | 保留已确认数据，修模板/测试后重建 | 重复写同一批数据 |
| 线上异常 | 记录 URL/HTTP/revision，按正式历史回滚 | 以单个 HTTP 200 宣布完成 |

每次批次记录：日期、内容 slug、语言、来源、媒体 SHA、D1/R2 回读、两次构建、CI/Pages revision、线上 URL、异常和回滚点。流程标准不随文章数、型号数或语言数改变。
