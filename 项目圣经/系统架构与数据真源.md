# XUYI 系统架构与数据真源

更新时间：2026-11-08

## 当前架构

- Cloudflare Pages 默认提供由 D1/CMS 快照生成的静态 HTML/CSS/JS；不运行常驻应用服务器。
- Pages Functions 只承担 Admin/API、询盘、媒体访问、发布状态和明确配置的动态回退，不把普通内容改成每次请求临时组合。
- D1/CMS 是产品、页面、Blog、评价、翻译、语言配置、导航、SEO 和 publish revision 的业务真源。
- R2 是原始图片和上传媒体真源；D1 保存媒体路径、ALT、语言和引用关系。
- `templates/site/`、共享渲染器和受控 CSS/JS 是结构与布局真源；不得手改生成页。
- GitHub Actions 是标准构建、测试、部署和线上验收控制器；当前版本以工作流、build-meta 和线上响应为准。

## 字段和数据所有权

| 内容 | 正式所有者 | 规则 |
| --- | --- | --- |
| 产品、分类、产品路由和可编辑字段 | D1/CMS + 受控源目录 | D1 已审核值优先；不使用固定产品总数或硬编码分类清单判断是否完整 |
| 语言、启用状态、publishReady、pathPrefix | D1 `site_state.language_config` | 所有语种枚举、路由前缀和发布判断读取配置，不在代码维护固定语种数组 |
| Blog 文章、列表卡片、翻译 | D1/CMS | 英文已发布集合和排序来自同一次 D1 查询；其他语种只重排已有审核卡片 |
| 页面 SEO、OG、canonical、hreflang | D1/CMS + 共享渲染器 | 后台值优先，构建时不得被旧基线或历史批处理覆盖 |
| 图片、ALT、媒体引用 | R2 + D1/CMS | 先核验/上传 R2，再条件写入 D1 引用；不得直接改 R2 缓存 |
| 公共结构和样式 | `templates/site/`、源渲染器、CSS | 一处修改，多处构建；不得改 `dist/` 或线上 HTML |

## 静态发布流程

D1/CMS 与 R2 读取 → 字段所有者/权限校验 → 条件写入与 publish revision → 两次干净构建 → 语言、SEO、链接、媒体和结构化数据回归 → GitHub Actions 部署 → build-meta、D1 revision 和线上路由回读。

静态包是默认访问结果。即使保留动态 Function，也不能把“请求时读取 D1”当成普通内容发布完成的替代方案。

## Blog 列表顺序

- 英文列表的完整已发布集合和排序以 D1 查询结果为唯一来源。
- 其他语言从 D1 language_config 枚举，只对已经存在且审核通过的本地化卡片按同一 slug 顺序重排。
- 缺卡、重复、额外卡、语言未配置或 D1 集合不一致时停止发布。
- 禁止按批次 slug 置顶、追加到末尾当作最终排序、修改 dist 或绕过 D1/CMS。

## 维护边界

- 历史日期脚本和审计文档只用于回放/核查；不能作为新的日常入口。
- 产品数量、语言数量、分类数量、路由数量、分页数量和 Blog 总数不写入本文件作为固定事实。
- 任何 AI/API/工具操作都必须遵守 AGENTS.md 的费用、权限、D1/R2、人工审核和回滚规则。
- 不导入无关项目的业务资料、品牌、数据库、密钥或媒体。
