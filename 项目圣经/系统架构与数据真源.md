# XUYI 系统架构与数据真源

更新时间：2026-11-08

## 当前架构

- Cloudflare Pages 默认提供由 D1/CMS 快照生成的静态 HTML/CSS/JS；不运行常驻应用服务器。
- Pages Functions 只承担 Admin/API、询盘、媒体访问、发布状态和明确配置的动态回退，不把普通内容改成每次请求临时组合。
- D1/CMS 是产品、页面、Blog、评价、翻译、语言配置、导航、SEO 和 publish revision 的业务真源。
- R2 是原始图片和上传媒体真源；D1 保存媒体路径、ALT、语言和引用关系。
- `templates/site/`、共享渲染器和受控 CSS/JS 是结构与布局真源；不得手改生成页。
- GitHub Actions 是标准构建、测试、部署和线上验收控制器；当前版本以工作流、build-meta 和线上响应为准。

## 字段和数据所有权

| 内容 | 正式所有者 | 规则 |
| --- | --- | --- |
| 产品、分类、产品路由和可编辑字段 | D1/CMS + 受控源目录 | D1 已审核值优先；不使用固定产品总数或硬编码分类清单判断是否完整 |
| 语言、启用状态、publishReady、pathPrefix | D1 `site_state.language_config` | 所有语种枚举、路由前缀和发布判断读取配置，不在代码维护固定语种数组 |
| Blog 文章、列表卡片、翻译 | D1/CMS | 英文已发布集合和排序来自同一次 D1 查询；其他语种只重排已有审核卡片 |
| 页面 SEO、OG、canonical、hreflang | D1/CMS + 共享渲染器 | 后台值优先，构建时不得被旧基线或历史批处理覆盖 |
| 图片、ALT、媒体引用 | R2 + D1/CMS | 先核验/上传 R2，再条件写入 D1 引用；不得直接改 R2 缓存 |
| 公共结构和样式 | `templates/site/`、源渲染器、CSS | 一处修改，多处构建；不得改 `dist/` 或线上 HTML |

## 静态发布流程

D1/CMS 与 R2 读取 → 字段所有者/权限校验 → 条件写入与 publish revision → 两次干净构建 → 语言、SEO、链接、媒体和结构化数据回归 → GitHub Actions 部署 → build-meta、D1 revision 和线上路由回读。

静态包是默认访问结果。即使保留动态 Function，也不能把“请求时读取 D1”当成普通内容发布完成的替代方案。

## Blog 列表顺序

- 英文列表的完整已发布集合和排序以 D1 查询结果为唯一来源。
- 其他语言从 D1 language_config 枚举，只对已经存在且审核通过的本地化卡片按同一 slug 顺序重排。
- 缺卡、重复、额外卡、语言未配置或 D1 集合不一致时停止发布。
- 禁止按批次 slug 置顶、追加到末尾当作最终排序、修改 dist 或绕过 D1/CMS。

## 维护边界

- 历史日期脚本和审计文档只用于回放/核查；不能作为新的日常入口。
- 产品数量、语言数量、分类数量、路由数量、分页数量和 Blog 总数不写入本文件作为固定事实。
- 任何 AI/API/工具操作都必须遵守 AGENTS.md 的费用、权限、D1/R2、人工审核和回滚规则。
- 不导入无关项目的业务资料、品牌、数据库、密钥或媒体。


## 可迁移架构与产品复用标准（2026-11-09）

本系统必须能在不改变核心后台能力的前提下，迁移到新的 GitHub 仓库、新的 Cloudflare 账号/项目，或复用为另一个 B2B 产品网站。迁移时严格区分三层，不能把三层混成一份复制文件。

### 一、三层边界

| 层 | 内容 | 是否随产品迁移 |
| --- | --- | --- |
| 系统核心层 | 模板、渲染器、Admin API、D1 schema、R2 引用规则、权限、构建测试、回滚机制 | 可复用，但必须先跑完整回归 |
| 部署适配层 | GitHub 仓库/Actions、Cloudflare Pages 项目、D1 数据库、R2 桶、Bindings、Secrets、域名和 DNS | 按新环境重新建立，不复制旧凭据 |
| 产品配置与业务层 | 品牌、域名、Logo、联系人、语言、导航、分类、产品、Blog、评价、媒体和 SEO | 同站迁移可复制；换产品必须新建或经过明确筛选迁移 |

系统核心层不得直接依赖某个品牌、域名、账号 ID、项目名、产品数量或语种数量。当前代码中保留的 XUYI 兼容索引和安全启动默认值只能作为旧站兜底，不是新产品的业务数据源。

### 二、两种迁移场景

#### A. XUYI 原站迁移到新的 GitHub/Cloudflare

目标是“数据不变、部署位置改变”。

1. 冻结后台写入，记录 D1 publish revision、当前 Git commit、线上 build-meta.json、sitemap、代表页面和 R2 引用清单。
2. 新建 GitHub 仓库/分支和 Cloudflare Pages 项目；重新创建 D1、R2、Pages Functions 绑定。
3. 迁移 D1 schema 与业务记录，迁移 R2 对象及对象键；迁移后先做行数、主键、语言、发布状态、媒体引用和 SHA 校验。
4. 在部署配置中替换新环境的 origin、Pages 项目名、D1 名称/绑定、R2 名称/绑定、生产分支和必要的 Cloudflare 账号信息。
5. 重新配置 GitHub Actions Secrets、Cloudflare Variables、ADMIN_TOKEN、IndexNow 等凭据；凭据不得从旧仓库、日志或导出文件复制。
6. 以临时域名或预览域名完成两次干净构建、CI、D1/R2 回读、全部已配置语种页面、Admin API 401 和关键线上路由检查。
7. 确认新站的 build-meta.sourceRevision、publish revision、sitemap、canonical、hreflang 和 R2 HEAD 正确后，再切换自定义域名/DNS。
8. 切换后保留旧 Pages 部署和旧 DNS 回滚窗口；新旧站均确认稳定后才解除旧资源。

#### B. 复用系统创建新的 B2B 产品/品牌站

目标是“复用系统能力，不复制 XUYI 业务数据”。

1. 只复制系统核心层、通用模板、Admin API、测试和发布流程。
2. 新建独立 GitHub 仓库、Cloudflare Pages 项目、D1 数据库、R2 桶和 Secrets；不得连接 XUYI 的生产 D1/R2。
3. 从空白 D1 初始化 language_config、品牌、联系人、导航、分类、字段、站点配置和发布策略。
4. 通过后台/API 导入新产品；图片先进入新 R2，再把路径、ALT、语言和引用关系写入新 D1。
5. 重新建立新产品的页面、Blog、评价、SEO、结构化数据和 sitemap；不得复制 XUYI 的产品描述、客户评价、审核记录或品牌声明。
6. 运行与原站相同的双构建、全语种、权限、媒体、索引和回滚验收；验收通过后才开放索引。

换产品时禁止直接复制 data/ 中的 XUYI 业务数据、functions/_shared/xuyi-routes.js 旧目录清单、历史 Blog/评价、生产媒体或旧站 canonical。需要复用的只能是经过确认的通用结构和测试规则。

### 三、迁移配置清单

迁移前必须逐项确认：

- deployment/site.config.json：品牌、origin、默认语言、Pages 项目、D1/R2 名称和绑定。
- Cloudflare：Pages 项目、生产分支、D1 数据库、R2 桶、Functions 绑定、环境变量、域名和 DNS。
- GitHub：仓库、main 分支、Actions 权限、并发组、Secrets、工作流触发条件。
- D1：schema、site_state、语言配置、发布 revision、产品/页面/Blog/翻译/评价/导航/媒体引用。
- R2：全部被 D1 引用的对象、对象键、媒体元数据、产品图和 Blog 封面。
- 公开入口：robots、sitemap、canonical、hreflang、404/重定向、Admin API 401、询盘和联系人。
- 安全项：ADMIN_TOKEN、Cloudflare Token、GitHub Token、IndexNow Key；只在新环境重新生成，不把旧值写入仓库。

### 四、迁移完成判定

迁移不是“代码能构建”就算完成，必须同时满足：

- 新 GitHub Actions 成功，至少两次干净构建一致；
- 新 Pages 的 build-meta.sourceRevision 与主线 commit 一致；
- D1 publish revision、产品/文章/语言/翻译记录和 R2 引用校验通过；
- 所有当前启用且 publishReady 的语种关键页面返回 200；
- Blog 列表顺序、产品分页、SEO、canonical、hreflang、sitemap 和结构化数据通过；
- Admin 未授权访问返回 401，后台人工读写只命中新 D1/R2；
- DNS 切换后线上回读通过，旧站仍可在回滚窗口内恢复。

任何一项失败，都停留在预览/草稿环境，不切换正式域名，不删除旧资源，不覆盖旧 D1/R2。

### 五、当前站点专属项

以下属于 XUYI 当前部署配置或兼容内容，迁移时必须重新确认，不能当作系统常量复制：

- XUYI 品牌、域名、联系人和默认语言；
- Cloudflare Pages 项目名、账号标识、D1/R2 名称和绑定；
- functions/_shared/xuyi-routes.js 的旧目录兼容索引；
- XUYI 的产品、Blog、评价、翻译、R2 媒体和历史审核记录；
- GitHub Actions 中的 XUYI 项目保护和生产分支条件。

换环境时先改配置和绑定，再迁移数据；换产品时先清空业务真源并初始化新配置。不得通过复制硬编码、替换生成 HTML 或直接改线上文件完成迁移。
