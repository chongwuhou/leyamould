# XUYI 架构与数据真源

## 技术层

- Cloudflare Pages：部署预渲染 HTML/CSS/JS/图标，不运行常驻应用服务器。
- Pages Functions：使用现有 `functions/` 提供询盘、D1 Blog、站点设置和 Admin API。
- D1：旭一 Blog、询盘、后台安全、网站联系人及语言设置、发布修订记录的生产数据真源。
- R2：现有真实产品、图库、集团已授权图片和 Blog 上传封面；静态图片走本域 `/media/`。
- 版本化 `templates/site/`：四个共享结构模板；导航链接仍由旭一的业务数据生成。
- `scripts/build_release.py`：把 `build.py` 生成的网页和允许公开的资源组装到 `dist/`。
- `scripts/preflight.py` 与 `scripts/test_release.py`：品牌/绑定/SEO/链接/文件数/模板一致性门禁。
- `.github/workflows/publish-xuyi.yml`：对标德玛隆的定时 D1 revision 检查和 CI 构建/部署控制器，依赖本仓库专用 GitHub Actions 凭据。

## Blog 多语言列表顺序

- 英文 /blog/ 实时页由 functions/blog/[[path]].js 调用 listBlogPosts(db,'published')，当前 D1 SQL 为 ORDER BY updated_at DESC；保持这一既有排序规则，不擅自改成 published_at。
- ES/PT/RU/TR 的 page:/blog/ 翻译记录保存各自的本地化卡片文案和 HTML，但完整卡片顺序必须与英文实时 D1 查询返回的全部 slug 顺序一致。
- 批量发布可先写入新文章和本地化卡片，但追加到列表末尾不是最终排序。写入后必须重新读取完整 D1 已发布列表，按返回结果重排四种语言的卡片块，只调整卡片位置，每张卡片内部 HTML 必须保持原样。
- 禁止按当天批次 hardcode slug 置顶，禁止直接改写静态 HTML 或 dist/。若卡片缺失、重复、额外或与 D1 集合不一致，必须停止发布；上线前后都要核对 EN/ES/PT/RU/TR 五份完整 slug 顺序。

## 无回归保证

迁移基线生成时 136 个预渲染页面 SHA256 全部未变，产物与历史根目录 HTML 一致；上线后按照 D1/R2、SEO、FAQ、联系人和不同语言分层回归。

## 隔离要求

生产构建只允许 `xuyi-drinkware-site`、`xuyi-drinkware-d1`、`xuyi-drinkware-r2`。
禁止把德玛隆 `CATALOG_DB`、`MEDIA_BUCKET`、`MODEL_PAGES_BUCKET`、品牌、产品数据、密钥引入旭一。

## Blog 翻译编辑与自动翻译边界

- Blog 多语言正文和列表都使用 `xuyi_translation_overrides` 的 `page:/blog/<slug>/` 资源，不新增静态文件数据源；后台正式页面编辑器从 D1 已发布 Blog 列表枚举这些路径。
- 翻译设置只有三态：关闭、自动翻译后人工审核、自动翻译后自动发布。默认关闭；Google 官方 Translation API 只有在后台明确选择并配置 Pages Secret 后才可调用，密钥不进入 D1。
- 定时发布器在新文章写入后再次按完整 D1 已发布列表重排四个多语 Blog 索引，并做条件更新和回读验证；因此不能用“追加到末尾”作为最终排序。
