# LEYA MOULD 统一内容、翻译与媒体发布标准

这是 LEYA MOULD 的人工后台、AI 草稿、正式 API、GitHub Actions、CMS 和后续自动化共用标准。执行顺序以《LEYA统一执行手册》为准；本文件定义字段所有者、质量门禁和可回滚证据。

## 1. 真源和字段所有者

| 内容 | 唯一真源 | 禁止作为发布源 |
| --- | --- | --- |
| 品牌、导航、产品/型号、News/Blog、视频、评价、翻译、页面 SEO、发布状态 | LEYA Cloudflare D1/CMS | `dist/`、线上 HTML、聊天记录、临时 JSON |
| 图片、封面、PDF 和媒体对象 | LEYA R2；ALT/语言/引用关系在 D1 | 本地临时文件、手工替换 URL、未核验对象 |
| 模板、Functions、渲染器、测试和发布规则 | GitHub 源码 | 直接修改生成页面 |
| sitemap、静态路由和 build-meta | 标准构建产物 | 手工上传的旧 HTML |

产品数量、语言、分类、排序、字段和公开状态必须实时读取 D1/config，历史数量不构成上限或验收标准。

## 2. 人工、AI 与正式写入边界

- 人工通过正式后台编辑；AI/脚本只通过已鉴权的正式 HTTPS API 写入同一套 D1/CMS 字段和 R2 引用。
- AI 只能做草稿、翻译初稿、结构整理、查重和审计，不可猜测钢材、穴数、尺寸、认证、MOQ、交期、客户、评价或图片事实。
- 没有明确发布授权只能只读或保存草稿；不能用浏览器、构建后替换或静态回退绕过正式写入。
- 禁止脚本、插件、自动化或 AI 直接写 `dist/`、线上 HTML、Pages 成品或 R2 缓存来冒充发布。
- 所有写入必须幂等、条件化、保留人工值、可回滚。冲突返回 409 时停止，不覆盖后台编辑；超时先只读确认，不盲目重试。
- 任何费用、额度、试用赠金或条款不明确的 API 禁止调用；密钥不得进入仓库、D1、日志或聊天。

## 3. 通用发布顺序

1. 读取最新 D1 snapshot、字段所有者、语言配置、发布状态和 revision。
2. 核对来源、重复主题、关键词蚕食、内链关系和媒体授权；形成可审计待发布批次。
3. 逐语言准备 Title、H1、Meta、正文、FAQ、按钮、ALT、OG、canonical 和 hreflang；型号参考、产品族、News、视频和评价遵守各模块字段。
4. 先审核并压缩媒体，核对 R2 URL、MIME、大小、SHA；成功后才把对象和 ALT 写入 D1。
5. 通过后台/API 条件写入 D1，读取插入/更新数量、语言集合、对象关系和 publish revision。
6. 从最新 snapshot 做两次干净构建，运行语法、真源、路由、模板、多语、SEO、链接和媒体回归。
7. CI/Pages 成功后回读 build-meta、r2-usage-index、列表/详情页、sitemap 和代表媒体 URL。

## 4. 模具内容和产品 SEO

- `leya_model_references` 的记录必须有稳定 slug、产品族、英文标题/ALT、来源页面、说明、排序、审核状态、翻译字段和 R2 引用。
- HMould、cap-molds 或其他公开资料只能标为参考来源。没有 LEYA 自有证据时，不写成“已交付型号”“现有认证”或“本厂实拍”。
- 每个型号 × 公开语言独立维护 Title、H1、Meta、OG、正文和 ALT；真实容量、材质、颜色、尺寸、认证、MOQ 和交期没有来源就留空或引导询盘。
- 页面须自然说明服务范围、适用场景和已核实优势，不把定制方向写成现有 SKU 的认证或库存事实。

## 5. News/Blog、视频与评价

### News/Blog

- 每篇只服务一个明确的 B2B 工程或采购意图，具备来源、独立信息、相关产品内链和询盘 CTA。
- 正文自然放入 2–5 个真实相关详情链接，文末人工选择 2–3 篇直接相关的已发布文章；不计导航、页脚和自动推荐。
- 列表统一按 D1 `ORDER BY COALESCE(published_at, updated_at) DESC, slug ASC`；所有 `publishReady` 语言使用相同 slug 集合和顺序。

### YouTube 视频

- D1 保存 URL、标题、多语标题/描述、分类、发布时间、缩略图和公开状态；列表发布时间只读后台字段。
- URL、状态或语言缺失时保持草稿；编辑/删除走视频模块 API，不改生成页面。

### 评价/案例

- 只接受有来源、授权且能核验身份/项目关系的评价；示意文案必须明确标示，不能冒充客户原话。
- 禁止为了版面生成星级、公司、国家、订单、交付结果或型号参数；图片不得冒充真实客户/工厂证据。

## 6. 翻译审计门禁

- 语言集合从 D1 `language_config` 的 `enabled + publishReady` 读取，不能写死语言数量。
- 每个公开语言必须拥有独立且完整的页面文案、SEO、结构化数据、按钮、面包屑、ALT、canonical 和 hreflang。英文 fallback 只能是明确的草稿/未发布状态，不能伪装成完成。
- 列表卡片、分页、详情路由和 sitemap 必须覆盖同一组已发布 slug。发现缺失、重复、额外卡片、串语、英文锚文本或错语言内链时停止发布。
- 翻译只由 D1/CMS 最终字段驱动；后台再次编辑后，以后台值为准，旧回退 JSON 不得覆盖。

## 7. GEO 和证据

- 先直接回答买家问题，再给参数、判断条件、适用/不适用边界、证据来源和下一步询盘。
- 优先使用清单、比较表、决策树、FAQ 和可核验数据；外部资料、案例和第三方链接必须注明来源或示意性质。
- 不发布空泛批量生成内容，不把 AI 图片、客户、认证、订单或测试当作真实证据。

## 8. 媒体与发布失败处理

- 图片实际查看后再记录场景、来源、授权、尺寸、格式、压缩结果、SHA 和 ALT。Blog 封面默认 1200×800、3:2、30–350KB；其他产品图按清晰度和体积审核。
- R2 上传超时先 HEAD/SHA 查询；D1 写入超时先读取记录和账本；确认未写入才重试。
- D1/R2 已写入但构建失败：保留正式数据，只修共享模板、测试或构建输入；不得重复写同一批内容。
- 线上异常：记录 URL、HTTP、source/publish revision，从 GitHub 或 D1/R2 正式历史回滚并重新构建。缺少全链路证据只能标记“待验证”。

本标准与《LEYA统一执行手册》不依赖固定文章数、产品数或语言数；任何新增模块都必须先补字段所有者、幂等条件、回归测试和回滚方式。
