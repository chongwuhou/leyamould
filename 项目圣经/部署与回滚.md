# XUYI 安全发布、缓存与回滚

## 正确构建

```powershell
cd D:\bendigpt-WebCodex\xuyi-drinkware-site
python scripts\preflight.py
python scripts\build_release.py
python scripts\test_release.py
```

只允许发布 `dist/`，不能再发布整个源码根目录：原始根目录发布模式曾使 `/build.py`、`/site_renderer.py`、`/data/products.json` 能被访问。

## 手工上线（现有 Wrangler 登录）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\deploy-production.ps1
```

检查 `https://xuyibottles.com/build-meta.json`，然后逐页确认首页、Blog、联系/询盘、产品和六个 Capabilities。
未登录时 `/api/admin/blog` 和 `/api/admin/publish` 应返回 401。
正式域名上 `/build.py?no_cache=...`、`/site_renderer.py?no_cache=...` 和 `/data/products.json?no_cache=...` 应为 404。

## 一键发布与 GitHub Actions

后台点击“一键全站重建”会将 D1 `site_state.publish_revision` 加一。控制器默认 30 分钟轮询，发现超过正式版 `build-meta.json.publishRevision` 后重新构建；推送源码和手动触发同样会构建部署。

**切换前提：** 必须为旭一仓库单独设置 GitHub Actions Secret `CLOUDFLARE_API_TOKEN`。Cloudflare Account ID 不是密码，已经作为普通 workflow 配置固定为旭一所在账号，不必重复设置 Secret。还需停用该 Cloudflare Pages 项目自身的 Git 自动 Production/Preview 部署，避免“双控制器”竞争或从旧源码根目录回滚上线。德玛隆保持原样。

凭据未配置前，CI 仅做构建和测试；不要称已实现自动部署。不要提交 Token 到仓库。

## CDN 缓存

如果旧源码 URL 正常访问返回 200，而加入新的查询参数后返回 404，说明旧资源可能被边缘缓存命中。通过 Cloudflare Dashboard 对 `xuyibottles.com` 执行针对性 URL 清理，必要时清理全站缓存；不能把旧缓存当成当前新构建仍公开源码。

## 回滚

保留 Cloudflare Pages 旧部署记录及本机 `_local_ops/xuyi-architecture-migration/project-source-before-migration.zip`。故障时优先在 Cloudflare 控制台回滚到已验证的上一 Production 部署，再排查 R2/D1/Functions；不要覆盖 D1 的业务数据做“代码回滚”。

## 站点索引门禁

上线不自动解除 `noindex,nofollow` 和 robots 拒绝收录；SEO 正式开放必须在内容合规、型号确认、hreflang 与 Form/隐私检查全部通过后单独审批。
