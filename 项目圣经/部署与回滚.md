# XUYI 发布、缓存与回滚

更新时间：2026-11-08

## 标准构建

在仓库根目录执行：

```powershell
python scripts/preflight.py
python scripts/fetch_build_snapshot.py
python scripts/build_release.py
python scripts/test_release.py
```

`build_release.py` 会重新生成干净 `dist/`。只发布 `dist/`，不发布仓库根目录，不手工改生成 HTML。

## 正式发布

- 后台修改业务数据后，确认 D1/CMS 写入成功并 bump publish revision。
- GitHub Actions 读取 D1/CMS 快照，完成双重构建、回归、Pages 部署和线上核验。
- 生产结果以工作流成功、`build-meta.json`、D1 publish revision 和线上关键路由回读为准。
- 仅有本地构建成功，不等于线上发布成功；仅有 D1 写入成功，也不等于静态页面已经上线。

## API 与动态边界

Pages Functions 保留 Admin/API、询盘、媒体、发布状态和明确的动态回退能力。公开普通内容默认来自静态构建；不通过浏览器、临时 HTML 或构建后正则替换发布内容。

## 安全检查

- 未鉴权 Admin API 必须返回 401；敏感源码、快照、Functions、模板和凭据不得进入公开 `dist/`。
- Cloudflare Pages 只允许 XUYI 自己的 Pages、D1、R2 绑定；不使用无关项目资源。
- 旧源码 URL 如果仍返回 200，先判断是否为边缘缓存，再按精确 URL 清理；不要用全站清缓存掩盖来源问题。
- 索引、robots 和 sitemap 以 `deployment/site.config.json`、build-meta 和线上响应为准，不能凭历史说明开启或关闭。

## 回滚

优先回滚到已验证的上一版 Cloudflare Pages 部署；随后检查 D1 revision、R2 引用、Functions 和线上关键路由。代码回滚不等于 D1/R2 数据回滚，禁止用代码回滚覆盖业务数据。

## 维护入口

- 变更规则：`AGENTS.md`、`PROJECT_CHANGE_POLICY.md`
- 仓库整理：`docs/REPOSITORY_MAINTENANCE.md`
- 脚本规则：`scripts/README.md`
- 数据目录：`data/README.md`
- 当前架构：`项目圣经/系统架构与数据真源.md`


## 迁移、新仓库与换产品执行卡（2026-11-09）

### 迁移前

- 先判断是“同一站点换部署环境”还是“复用系统做新产品”；两者禁止混用数据。
- 冻结写入并记录 Git SHA、D1 publish revision、线上 build-meta、D1/R2 清单和回滚版本。
- 导出/备份只允许进入受控位置；检查导出文件不包含 ADMIN_TOKEN、Cloudflare Token、GitHub Token、邮箱密码或其他凭据。

### 新环境初始化顺序

1. GitHub：新仓库、默认分支、Actions 权限和 Secrets。
2. Cloudflare：Pages、D1、R2、Functions、Bindings、Variables。
3. 配置：域名、品牌、语言、联系人、导航、分类、字段、索引策略。
4. 数据：同站迁移 D1/R2；新产品使用全新 D1/R2，只导入确认过的数据。
5. 构建：预览环境两次干净构建和完整回归。
6. 域名：最后才切换 DNS/自定义域名。

### 禁止事项

- 不把旧 Cloudflare 账号 ID、Pages 项目名、D1/R2 名称、域名或 Secret 当作通用值。
- 不让新产品连接旧站 D1/R2，不把 XUYI 的 Blog、评价、图片或客户资料带入新产品。
- 不通过复制 dist/、线上 HTML、R2 缓存或浏览器页面迁移业务内容。
- 不在迁移过程中同时修改模板、数据结构、语言规则和品牌配置；需要拆成可回滚的小步骤。
- 未完成线上回读前，不删除旧仓库、旧 Pages、旧 D1/R2 或旧 DNS。

### 回滚顺序

1. 先恢复 DNS/域名到上一个已验证的 Pages。
2. 业务数据保持原 D1/R2 不变；不要用代码回滚覆盖 D1。
3. 检查 publish revision、静态 build-meta、Functions、关键页面和 Admin API 权限。
4. 记录失败阶段和差异，修复后重新从预览环境开始；不得在生产直接反复试错。
