# XUYI 发布、缓存与回滚

更新时间：2026-11-08

## 标准构建

在仓库根目录执行：

```powershell
python scripts/preflight.py
python scripts/fetch_build_snapshot.py
python scripts/build_release.py
python scripts/test_release.py
```

`build_release.py` 会重新生成干净 `dist/`。只发布 `dist/`，不发布仓库根目录，不手工改生成 HTML。

## 正式发布

- 后台修改业务数据后，确认 D1/CMS 写入成功并 bump publish revision。
- GitHub Actions 读取 D1/CMS 快照，完成双重构建、回归、Pages 部署和线上核验。
- 生产结果以工作流成功、`build-meta.json`、D1 publish revision 和线上关键路由回读为准。
- 仅有本地构建成功，不等于线上发布成功；仅有 D1 写入成功，也不等于静态页面已经上线。

## API 与动态边界

Pages Functions 保留 Admin/API、询盘、媒体、发布状态和明确的动态回退能力。公开普通内容默认来自静态构建；不通过浏览器、临时 HTML 或构建后正则替换发布内容。

## 安全检查

- 未鉴权 Admin API 必须返回 401；敏感源码、快照、Functions、模板和凭据不得进入公开 `dist/`。
- Cloudflare Pages 只允许 XUYI 自己的 Pages、D1、R2 绑定；不使用无关项目资源。
- 旧源码 URL 如果仍返回 200，先判断是否为边缘缓存，再按精确 URL 清理；不要用全站清缓存掩盖来源问题。
- 索引、robots 和 sitemap 以 `deployment/site.config.json`、build-meta 和线上响应为准，不能凭历史说明开启或关闭。

## 回滚

优先回滚到已验证的上一版 Cloudflare Pages 部署；随后检查 D1 revision、R2 引用、Functions 和线上关键路由。代码回滚不等于 D1/R2 数据回滚，禁止用代码回滚覆盖业务数据。
